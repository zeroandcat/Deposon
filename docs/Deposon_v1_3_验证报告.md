## 一、执行摘要

本轮推进完成了 v1.2 路线图中的头号阻塞项 **P0-1**：将 LLM 后端从规则引擎占位升级为真实 Kimi API（kimi-for-coding），并修复了导致 v1.2 全部消融实验 **effect_size = 0.0** 的两个根因机制缺陷。

核心结果（相对 v1.2 的变化）：

1. **简单100题**：效应量 0.0 → **+0.93**（unified 100% vs no_deposon 7%）
2. **陷阱100题**：效应量 0.0 → **+0.84**（unified 97% vs no_deposon 13%）
3. v1.2 中规则引擎无法识别运算的 "unknown" 题目：**0% → 100%**
4. 物理审计保持通过：t+r+a 幺正性最大偏差 2.2e-16（< 1e-6 容差）
5. 全部 199 个评测问题均使用真实 API 分解结果，**0 条规则降级**

## 二、本轮完成内容

### 2.1 真实 KimiLLMBackend（deposon_agents_v1_3.py）

- **decompose()**：LLM 输出严格 JSON（数字角色与顺序、多步运算链、陷阱标注、computed_answer），替代 v1.2 的关键词正则引擎。多步运算（"先打八折再满减"类）由运算链显式表达。
- **validate()**：真实 API 验证推理链逻辑（冒烟实测 verdict=correct, score=1.0；百题评测中为控制配额消耗默认关闭，runner 提供 `--validate-samples` 抽样开关）。
- **generate_answer()**：真实自然语言答题。
- **自动降级**：API 失败 / JSON 解析失败 → 完整保留的 v1.2 规则引擎，计入 fallbacks 统计。离线冒烟验证降级路径可运行、不崩溃。
- **持久化缓存**：sha256(kind|prompt_version|query) 键、线程锁、原子写（os.replace）。五变体共享分解缓存，每题仅 1 次 API 调用。

### 2.2 v1.2 效应量恒 0 的根因修复（本轮最重要的机制贡献）

| 根因 | v1.2 缺陷 | v1.3 修复 |
| --- | --- | --- |
| 根因一 | 答案直接从图节点启发式计算，与 Deposon 散射筛选结果完全脱钩——无论物理层如何过滤，答案不变 | 答案沿「Deposon 筛选后的存活路径」计算（通过者优先，否则全体最高分） |
| 根因二 | 陷阱节点是死胡同，BFS 路径生成永远不会经过，物理层无陷阱可挡 | LLM 标注的陷阱以高权重边（0.9）构成「诱饵路径」通向 Goal；贪心探索优先进入陷阱 → no_deposon 被捕获（7%/13%）；陷阱节点 g_couple=5.0（反射率 0.84）在 v1/unified 模式下被散射阻断，正确链胜出（100%/97%） |

附带修复：BFS 邻居截断 4→8（v1.2 中陷阱边 ≥4 条时会把正确链入口挤出候选，这是 v1.2 unknown 类全错的部分成因）；修复 v1.2 源文件一处语法错误（原文件无法通过 ast.parse）。

### 2.3 消融故事自洽性

v2_tunneling 在陷阱题上为 84%，低于 unified 的 97%：全局 g_aether≥2 导致过度耗散，正确链能量也被耗入以太。这与统一场论预测一致——v2 是「全耗散」极限态，混合态才是工作点。五变体构成完整的剂量-效应曲线。

## 五、残留问题与诚实边界

### 5.1 surface_division 残留 3 题

「每组49人一共8组，平均每班几人」类——文字歧义极强（金标为乘法 392）。prompt v1.3.1 迭代已修复该模式的 7/10，但剩余 3 题的重试恰逢 **API 配额耗尽**（HTTP 403 usage limit，计费周期未刷新），只能复用旧 prompt 的缓存结果。配额恢复后删除对应 3 条缓存重跑即可，预期 traps unified → ~100%。

### 5.2 评测公平性声明（重要）

本轮消融的图由同一个 LLM 分解器生成（五变体共享），陷阱由 LLM 标注。因此效应量度量的是：**在同一张图上，「Deposon 物理层筛选路径」相对「无物理层的贪心路径选择」的增量价值**。这是消融实验的正确设计，但不等价于「Deposon 系统优于 LLM 本身」——后者的验证需要 P0-2（真实 GSM8K 子集 + CoT/ToT 基线对比）。

### 5.3 validate 层未全量启用

为控制配额消耗，百题评测中 LLM validate 默认关闭，仅冒烟与抽样验证其真实可用。v1.4 应将 validate 纳入主评测环路。

### 5.4 配额风险

开发期间曾触发限流（8 并发下产生 82 条降级缓存，已用真实结果覆盖）。建议生产使用时并发 ≤4 并监控 403。
