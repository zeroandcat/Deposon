- 登记时间：2026-08-30，先于任何 GT-2C 运行结果写入（先写后跑）。
- 前身：GT-2B 判 inconclusive（docs/Findings_GT2B.md §4：固定 4 选项 ⇒ 图内候选数随 T 反比变化，「场免疫」判据被选项构成污染；n=40/格功效不足）。
- 零 LLM API：仅复用 `results/gt2_attacker_cache` 既有缓存；llm_prior 臂不跑。
- 执行脚本（待写）：`run_v20_gt2c.py` → `results/deposon_v20_gt2c.json`。

## 1. GT-2B 教训 → 本版设计修复

| GT-2B 缺陷 | GT-2C 修复 |
|---|---|
| 固定 4 选项 ⇒ 陷阱强度 T 与图内候选数耦合 | **可变选项数**：选项 = 金 + T 陷阱 + K 图内随机节点，K 固定=4，T∈{1,2,3} ⇒ 图内候选数恒定，机会水平随 T 变（1/6、1/7、1/8）——如实按变机会水平解读 |
| 准确率被选项构成污染 | **免疫判据改写为排序级**：field_mean 的免疫不考准确率，考「金边在图内候选中的排序位次」是否随 T 变（陷阱 -inf 不进排序域 ⇒ 位次应不变） |
| n=40/格，±2.5pp 噪声 | **配对检验**：同题跨 T 档配对（McNemar），非配对比例检验；每格 n=80（题库翻倍，同种子延展） |
| 陷阱模取复用、题间非独立 | 披露保留（缓存上限），但在配对设计下同一题三档共用同批陷阱前缀，部分对冲 |

## 2. 假设

- **H_GT2C（主）**：rule_filter 准确率随 T 单调不增（配对 McNemar：T=1→3 显著下降或持平；允许平台，不允许显著上升反转）。
- **场免疫零假设（排序口径）**：field_mean 金边排序位次（在图内候选中的 rank）在 T 三档间不变的比例 ≥ 95%（容差：数值并列扰动）。
- **机会水平校正**：全部臂的准确率同时报原始值与机会校正差（acc − 1/(2+T+K)）。

## 3. 判死线 / 支持线（预登记，先承诺）

- rule_filter T=1→3 配对检验显著**上升**（p<0.05 且方向为上）⇒ **H_GT2C_dead**。
- 单调不增且至少一档显著下降 ⇒ **supports_H_GT2C**。
- 其余（不显著、非单调但不显著）⇒ **inconclusive**，归档不回溯。
- field_mean 排序不变比例 < 95% ⇒ 免疫主张降级为「近似免疫」，如实披露并列位次偏移分布。

## 4. 设计参数（冻结）

- 题库：BANK_SEED=20260828 延展逻辑，4 域 × 20 题 × T 三档；crc32 稳定哈希；`np.random.default_rng` 显式种子；结果 JSON 无运行时字段，同种子逐字节一致。
- 臂：rule_filter / field_mean / random（种子化）。域：同 GT-2B 的 4 域（缓存约束），如实披露。
- 陷阱取法：题 k 的 T 档取缓存前缀 `traps[(k*3 + j) % len(traps)], j<T`——三档共享前缀，配对可比。

## 5. 统计

- 主检验：McNemar 配对（T=1 vs T=3，及逐相邻档）；报精确 p。
- 排序免疫：位次不变的逐题比例 + 偏移分布直方数据。
- 功效说明：n=80/格下 McNemar 对 ≥15pp 的下降有约 80% 功效（近似），小于此幅度的梯度仍可能 inconclusive——如实写入结论。
