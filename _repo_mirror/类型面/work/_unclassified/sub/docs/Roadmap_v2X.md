# Roadmap v2.X — Deposon 模型假设的潜力与边界探索（初步计划）

> 2026-08-23 起草。前提：本月额度封顶，本计划不含任何需立即执行的 API 实验；
> Phase 0 全部为零额度工作，Phase 1+ 待下月恢复。
> 三条核心思维贯穿：**大材小用**（重机制只打可验证的小靶点）、**落到实处**（每阶段有可检查交付物）、**与死同行**（每个假设自带预登记斩杀线，阴性结果一等公民）。
> 继承：docs/LESSONS_v19.md 全部 18 条；docs/Roadmap_v1.9.md 的 P1–P3 与决策点。

## 0. v2.X 的核心科学问题

v1.9 之后，Deposon 的假设空间已被压缩为三个可证伪命题：

- **H-A（潜力）**：mean-field 场是「骨架检测器」——在有向层级/汇聚结构上，纯物理场对骨架边排序达到天花板（单图 named=1.000）。
- **H-B（边界）**：场信号对叶部/ filler 原理性缺失（filler=0.088），单信号 overall 稳健不可得；overall 只能主张非劣效。
- **H-C（价值锚点）**：相对 6 关键词规则等平凡基线，LLM+物理管线在本类任务上增量为零——**v2.X 的存在意义就是找到增量非零的场景，或诚实宣布没有**。

v2.X 的唯一成功标准：**在多图、多场景上把 H-A/H-B 的成立域画出来，并对 H-C 给出至少一个反例或一次彻底证伪。**

## 1. 版本规划总览

| 版本 | 主题 | 场景 | 额度需求 | 斩杀线（与死同行） |
|---|---|---|---|---|
| **v2.0** | 多图地基 | 脑图（延续） | **零**（ConceptNet/Wikidata 免费 + 缓存） | H-A 跨图不复现 → 转「适用边界」论文 |
| **v2.1** | 场景迁移一 | 代码依赖图补全 | 零～低（真实标签，无需 LLM 先验） | 场不优于 Adamic-Adar → 该场景判死 |
| **v2.2** | 场景迁移二 | Agent 工具调用 DAG 审计 | 中（需新 LLM 缓存） | 守恒账相对规则过滤零增量 → 判死 |
| **v2.3** | 耗散通道终审 | 迭代重搜推理（GSM8K 多轮） | 中 | 耗散收益仍为零 → 「不可逆耗散」卖点永久下线 |
| **v2.4** | 整合判决 | 跨场景元分析 | 低 | 无一场景过平凡基线 → H-C 证伪成立，项目转型 |

（v2.1 起不局限于脑图，但每个场景独立成版、独立斩杀，不贪多。）

## 2. v2.0 多图地基（本月可启动，零额度）

**目标**：把「单图个案」升级为「图级统计」，这是 v1.9 Roadmap 的 P1，也是一切后续版本的地基。

- 语料三轨（≥12 张、≥3 来源，R3 标准档）：
  1. ConceptNet/Wikidata 采样子图（40–60 节点、方向定义明确、免费、天然支持 KGE 基线）——**本月可做**；
  2. 真实脑图（XMind/课件/教科书目录）双人转译 + κ 一致性——人工活，零额度；
  3. LLM 生成+人审（声明与先验臂同源污染风险）——留到下月。
- 管线迁移：mean-field init 设为默认、全候选排序协议、tie-break 改内容哈希、图级 cluster bootstrap + Holm。
- 平凡基线组先行（教训 #4）：Adamic-Adar/Jaccard、label 嵌入余弦、规则过滤——**在跑 Deposon 之前先全部跑完**。
- SPEC v2.0 预登记：主终点 named Hits@3 图级符号检验（α=0.05）；overall 非劣效（TOST 0.03）；分析代码先于数据入库并记录哈希。
- **斩杀线**：H-A 跨图不复现（符号检验不显著或效应反转 ≥3 图）→ 按 v1.9 决策点转「物理约束层适用边界」论文，不硬撑。

**本月零额度交付物**：ConceptNet 采样脚本 + ≥6 张图、SPEC v2.0 预登记、基线组结果 JSON。

## 3. v2.1 代码依赖图补全（下月，零～低额度）

**选景理由**（大材小用）：真实标签（import/call 边客观存在）、无需 LLM 先验即可跑场臂、负样本天然、与脑图结构互补（非辐条汇聚，检验 H-A 是否本图特例——v1.9 开放问题 #1 的最便宜回答）。
- 数据：开源仓库依赖图（标准工具解析，零额度）。
- 实验：field_mean vs Adamic-Adar/Jaccard/KGE（多图后可训练 TransE/ComplEx）vs 规则基线。
- **斩杀线**：场不优于 Adamic-Adar（免费、经典）→ 该场景判死并归档 `_negativeresult.json`。

## 4. v2.2 Agent 工具调用 DAG 审计（需新缓存）

**选景理由**：v1.4 基准叙事的合法继任者——工具调用链的「陷阱步骤」剪枝 + 守恒账审计是 Deposon 叙事最自然的落地；但必须先过 v1.9 的两个教训：
- 中性化审计前置（教训 #3）：建图时禁用一切免费 `type` 标签泄漏，等权对照、BFS 偏好对照从第一天就是标配臂；
- 平凡基线前置（教训 #4）：规则过滤、单一 LLM 直答（直接 CoT 基线——补上评审唯一遗留 fail 项）。
- **斩杀线**：守恒账相对规则过滤零增量 → 判死。

## 5. v2.3 耗散通道终审

- v1.9 已证：当前全部场景耗散零可测收益（v1_blocking ≥ unified 处处成立）。唯一理论上可能激活耗散的场景是**迭代重搜**（多轮展开、错误模式跨轮重生）。
- 设计：GSM8K 多轮重搜协议，unified（带耗散）vs v1_blocking（零耗散）预登记对比。
- **斩杀线**：仍零收益 → 「不可逆耗散」从卖点永久降级为设计遗产，论文 §3 再降格——这是「与死同行」的示范执行。

## 6. v2.4 整合判决

跨场景元分析：H-A 成立域（何种图结构）、H-B 边界形貌、H-C 最终判决。
- 若全场景区零增量：H-C 证伪成立——产出《物理约束散射层的适用边界》论文（problem-inversion 策略 2），这不是失败，是 v1.9 就预登记的合法终点。
- 若某场景过平凡基线：该场景升级为 v3.0 主线。

## 7. 纪律清单（每版本强制）

1. SPEC 预登记先于数据；修正案留痕；阴性结果 `_negativeresult.json` 归档。
2. 平凡基线 + 中性化对照先于主实验；缓存带 sha256；verifier 新版本 + runs 全记录。
3. 论文只由独立助手改；双评审（方法论 + 写作）+ 独立复核三角色不变。
4. 密钥仅单次命令内联；verifier 红线扫描每轮必查。
5. 每个版本开工前先问：这一版的「死法」写清楚了吗？（与死同行的操作化）
