### §1.7 立准：判据之基座如何换

- **弃**：以「活引用数／快照提及数」定去留（勘查件 §2-1 之判据列）。其病＝PI 逐字所指——「很多需要归档或清里的却上传」：引用多只说明**有人提过**，不说明**值得留、值得传**。
- **立**：以**件之内容属性**（体裁／名式／首行语义／所在面／mtime／可复算性）定去留与上传；引用数**降级为辅证**，仅用于「重复副本之取舍」与「幽灵引用之登记」，**不得单独决定去留**。
- **尺**：**件数**为唯一判据。体积**不作判据**、**不作处置理由**、**不作上传取舍之依据**；体积大之面（DB 备份／sessions／sqlite／缓存之类）**不在本规则之整理目标**——既不因体积而处置，亦不因体积而裁上传。
- **面（PI 18:0x）**：**归档区不上传** ⇒ ① 上传面之**分母只有「repo 去 `.tmp` ＋ sub」**，远端对账**不含归档区**；② 归档区**非处置容器**——件入归档区之唯一理由 ＝ **内容类判定（不上传留档件）**，**⛔0 不以「移入归档区可减上传面」为由去堆**；③ 归档区骨架化之**成效指标 ＝ 可寻址性／目录数**，**⛔0 写「减少上传件数」**；④ 日志面**已定性 ＝ 正当留存**（仅供复核·几无干扰）⇒ **冻结令不变·非待议例外**。
- **「件数为尺」⛔0 与「凑件数」混读**：前者是**以件数为判据**；后者（已作废）指为「两区件数拉平」而人为凑数之测算。⇒ 本件**不产出凑数之测算**，只产出**内容驱动之件数减项**。
- **存**（MEMORY 2026-09-28 惯例之未与判据冲突者）：「垃圾＝用完即弃且后续无需复核」⇒ 可恢复删除；「项目衍生件 → sub」；「不上传留档件 → 归档区」；「拿不准 → 留＋问」；「权威件禁转移」；**「唯一生成器／可复算性优先于主仓去核心化」**；「转移前先重生成追踪 manifest」。
- **增**：**上传面**作为独立判据轴（本地留存 ≠ 上传）；**状态闸**（在途件禁动、暂不上传）；**冻结面**（PI 明令不动之面，规则对其不生效）。

## §3 目录统一规则（Dir Rule）

### §3.1 骨架（层数·每层语义·命名式样）

```
<区根>/<面 facet>/<子类 subfacet>/[<桶 bucket>/]<件名>
```

| 层 | 语义 | 取值 | 命名式样 |
|---|---|---|---|
| 区根 | 件所属之本地区 | `deposon-repo`／`deposon-sub`／`〔归档区〕` | 沿用现名（⛔0 改名） |
| **面 facet** | 件之**内容属性**（唯一承重之层） | **9 个封闭词表**：`source`／`readout`／`verdict`／`doc`／`evidence`／`media`／`work`／`tool`／`review` | 小写下划线 snake_case，英文，⛔0 中文、⛔0 空格、⛔0 日期 |
| **子类 subfacet** | 面内之**用途细分** | **22 个**，与内容判据 22 类一一对应 | 同上 |
| **桶 bucket** | 大族之**时间切片**（可选层） | `d<YYYY-MM-DD>`（件之 mtime 之本地日期） | 同上；族量 ≤ 2,000 件者**不设此层** |
| 件名 | 件之个体 | 沿用原 stem；**冲突时**加 `__<sha12>` 后缀 | 保留原名（⛔0 批量改名——改名即失引用）；日期留在内容与 mtime，**不入目录名**（实测：归档区 19,288 个 `bg_*` 目录名 0 个含日期 ⇒ 目录名不承载时间） |

**「什么进哪一层」之判定式**（＝ §4 类别判定式，无第二套口径）：
> 件 → 跑 §4.2 之裁决序 → 得**类** → 该类在 §4.1 表中之 `(面, 子类)` ⇒ 该件落 `<面>/<子类>/`。桶层由该族**件数**与件之 mtime 机械推出。**判定不依赖「被引用几次」，亦不依赖体积。**

**层级恒定**：件必在第 3（或 4）层；面／子类／桶皆由封闭词表定 ⇒ 机器可解析、diff 可读。

### §3.2 四处之同一性（规则如何同时管 repo／sub／归档区／镜像区）

| 面 | 规则如何落 |
|---|---|
| `deposon-repo` | 现存顶层目录（`results\`／`pi_rulings\`／`docs\`／`paper\`／`scripts\`／`tools\`／`corpus\`／`verifier\`／`attacks\`／`reviews\`／`letters\`／`deposon_team\`）**经「声明映射」升格为规则之 slot**（例：`pi_rulings\` → `verdict/pi`；`run_*.py` 族 → `source/tool`；`results\` 之读数 → `readout/final`）；**⛔0 批量改名**（见 §3.3 代价） |
| `deposon-sub` | 同上（`sub` 无独立面，件按内容归入同一 22 类） |
| 归档区 | **在射程面**（1,704 件／125 目录）**按规则物理重整**（→ 19 目录）；**冻结面**不适用（§3.6.1） |
| 镜像区 | 规则之**纯粹形态**：`<面>/<子类>/<件名>`，**无区根段** ⇒ repo 与 sub 之件同处一个命名空间（约束 A） |

### §3.3 落地之三径（代价不对称·候 PI 裁·**唯尺为件数**）

| 径 | 内容 | 移动**件数** | 路径失效面（实测·处数） | 可逆性 | 代价 |
|---|---|---:|---:|---|---|
| **甲·声明映射（增量）** | 现有目录声明为 slot；**新件与移入件**一律按规则落位；镜像区取纯粹形态 | **0**（仅移入件按规则入位） | **0**（既有引用全断链） | 高 | 规则**看得见但不彻底**：现存树仍是旧名，镜像区才是规则之全形 |
| **乙·全量重整** | repo＋sub 全部按规则重排 | **8,226**（repo 6,950＋sub 1,276；仓为活面，18:0x 读数较 §2.1 之 17:44:13 多 2 件） | **330,878 处**相对路径引用＋**40,593 处**绝对路径引用（须逐处补「旧→新」登记） | 低（须 manifest＋分批＋回滚） | **高**：断链面十万量级，远端镜像亦须整体重推 |
| **丙·镜像纯粹＋本地增量（荐）** | 镜像区取规则纯粹形态；本地走甲；归档区仅在射程面物理重整（1,704 件） | **1,704**（归档在射程面）＋镜像区重推 2,983 件 | 归档在射程面之引用面（须逐面实测，⛔0 假设） | 中 | 中；且**上传面收窄可先行见效**（径甲之甲） |

⇒ **荐丙**：PI 之令之核心诉求（「凭内容决定去留」「上传面收窄」「镜像区不分家」「路径改云端」）**皆可在不搬既有件之前提下达成**；乙径之十万量级断链面与「零移动」之铁律不合。

### §3.4 镜像区之单一命名空间与**同名消解**（约束 A）

**命名空间**：镜像根保留现名 `_repo_mirror/`（⛔0 改名——改名即断远端既有引用）；其下路径 ＝ `<面>/<子类>/<件名>`，**无 repo／sub 之段** ⇒ 两者同处一个命名空间。

**同名消解规则（确定性·幂等·可查）**：
1. **同内容去重**：若两件之 **SHA-256 相同**且落位后 `<面>/<子类>/<件名>` 相同 ⇒ 实为一件，**只上传一次**；manifest 记双源（本地两址 → 同一云端址）。
2. **异内容加后缀**：若 SHA-256 不同而云端路径相同 ⇒ 两者皆上传；按排序键 `(SHA-256 十六进制小写字典序, 源区序 repo<sub, 原相对路径字典序)` 取**先者为基准名（保留原名）**，后者加 `__<sha12>` 后缀（`<stem>__<sha12><ext>`）。⇒ **同输入必同输出**：排序键只依赖内容哈希与路径，与执行顺序无关；重跑幂等。
3. **不可逆性之补**：后缀法**不可由云端路径反推原名**（哈希非原名之函数）⇒ **manifest（`本地绝对路径 ↔ 云端相对路径` 双向索引）为唯一反查凭据**——「可查」而非「可逆」，故 manifest **先于上传生成并随镜像同存**。

**实测冲突面（自测·17:5x·以件数为据）**：按 `(面,子类,件名)` 三元组计，repo＋sub 之上传面内**同名冲突 25 组／涉 105 件**；若按**扁平单层**（无面／子类层）计，则同名组更多（`same-BASENAME 跨区 ＝ 120 件`；`同相对路径跨区 ＝ 12 件`）⇒ **分层确能消解大部分冲突**，余 25 组由上述后缀规则收敛。
**样例**：`README.md`（repo，`a80b3db006a5`）与 `verifier\README.md`（sub，`d76f2dc473be`）二者落 `doc/readme/` ⇒ 哈希小者（`a80b…`）保 `README.md`，另一者落 `README__d76f2dc473be.md`。

### §3.5 云端路径改写规则（约束 B）

**规则（确定性映射·同输入必同输出）**：

```
云端路径(本地绝对路径 P) =
    ① 剥前缀 "〔本地路径已脱敏〕" ⇒ 得 <区根>\<rest>
    ② 丢区根段（repo／sub／archive 均不入云端路径）   ← 约束 A 之落地
    ③ 依 §4.2 裁决序求 P 之 (面, 子类)                  ← 内容判据，纯函数
    ④ 桶层：若该 (面,子类) 族件数 > 2,000 ⇒ 加 d<mtime 日期>；否则不加
    ⑤ 件名：原 stem；同路径冲突者加 __<sha12> 后缀（§3.4 规则 2）
    ⇒ "<面>/<子类>/[<桶>/]<件名>"
```

**可逆性**：⛔0 不可由云端路径反推本地绝对路径（本地根因机而异）⇒ 靠 **manifest 双向索引**「可查」；**凡涉路径之引文，⛔0 回改原引一字**（沿前案铁律），以查表代之。

#### §3.6.4 件不丢之保全机制（在射程面重整时必行）

1. **台账先行**：先落 manifest（在射程面 1,704 行：旧路径／SHA-256／新路径／新件名／桶键／类／上传面标记）；落盘后核验「行数 ＝ 1,704」且「逐行 SHA-256 与盘上件重算相符」⇒ **缺 0 件、篡改 0 件**。
2. **分批**：每批 ≤ 200 件（按 `(面,子类)` 族为单位）；每批后复扫**件数**。
3. **零删除**：重整只移动／改名，**不删除**（删除另走可恢复通道，且须 PI 逐单）。
4. **可逆**：manifest 记旧路径与旧件名 ⇒ 可反查、可回滚。
5. **失败即停**：任一批件数或指纹不符 ⇒ 停手并按 manifest 回滚，**⛔0 续跑**。
6. **引用面登记**：凡路径式引用（§2.4 之 `results/...` 式等）指向被移动之件者，须逐处补「旧路径 → 新路径」登记（**⛔0 回改原引一字**）。

> **白话**：判据只问「这是一件什么东西」，不问「它被提过几次」，亦不问「它多大」。「可复算」＝ 能由在册的唯一生成器重新算出来。

**类别 ＝ 落位**：每类恰落一个 `(面, 子类)` ⇒ **22 类 ↔ 22 个 (面,子类) 对**，故「什么进哪一层」**无第二套口径**（§3.1）。

⚠ **「去处 ＝ 归档区」之义（PI 18:0x）**：归档区**不上传**，故「归归档区」之意义 ＝ **本地留档（不上传之件之留底）**，**⛔0 非「减上传面之手段」**，**⛔0 以此为由堆之**；件之归档与否**唯由其内容类决定**（不上传留档件之归口）。

### §4.2 判定优先级（显式裁决序·先命中先判·⛔0「视情况而定」）

```
G0 状态闸（在途闸）  mtime ≥ 当日 00:00 ⇒ 状态 ＝ 在途
                     ⇒ 禁动（不移动/不改名/不删）＋ 暂不上传
                     （闸只改「处置」，不改「类」；类仍照判，供俟其毕后归位）
   │
R0 机械特判（体裁无关·先于一切语义判据）
   R0.1 size ＝ 0                        ⇒ W-EMPTY
   R0.2 扩展 ∈ {.pyc,.pyo}               ⇒ W-BUILD
   R0.3 扩展 ∈ LOGEXT                    ⇒ W-LOG
   R0.4 stem ∈ 工艺件名 且 文本件          ⇒ W-LOG
   R0.5 所在目录 ∈ WORKDIR               ⇒ W-SCRATCH
   R0.6 路径含快照面标记                   ⇒ X-SNAP
   │
R1 权威面（所在面）  位于 pi_rulings\     ⇒ V-VERDICT
   │
R2 体裁（扩展名）
   R2.1 代码扩展                          ⇒ S-SRC
   R2.2 数据扩展                          ⇒ R-INTERIM（名含中间态标记）否则 R-FINAL
   R2.3 媒体扩展                          ⇒ M-MEDIA
   R2.4 文本扩展                          ⇒ 入 R3 语义
   R2.5 其余                              ⇒ X-UNK
   │
R3 语义（名式 ＋ 首行前 170 字·关键词序·先命中先判）
   V-KD → V-VERDICT → V-JUDGE → X-REVIEW → D-PAPER → D-LETTER
   → D-README → D-REPORT → D-PLAN → R-FINAL → E-EVID ⇒ 皆不命中 ⇒ W-SCRATCH
   │
R4 结构件  stem ∈ STRUCT集                ⇒ T-STRUCT
   │
R5 重复覆盖（末层·覆盖以上诸判）  SHA-256 与他件同 且 非基准件 ⇒ X-DUPE
```

**裁决序之理由（可复核）**：① 先机械（体裁客观、无歧义）；② 再权威面（PI 明裁之面不容语义猜度）；③ 再体裁；④ 再语义（关键词序使「一条件像两类」有唯一裁决）；⑤ 结构件与重复为**末层覆盖**（因其是「件之个别性」而非「件之种类」）。

### §4.3 上传面之收窄机制（通则·三面）

> **白话**：「上传面」＝ 允许传到远端的那批件。本地留着 ≠ 该传远端。

**① 必不上传（9 类 ＋ 2 条状态／面之限）**
- `W-LOG`／`W-EMPTY`／`W-BUILD`／`W-SCRATCH`／`X-UNK`（工作面与不明件）
- `R-INTERIM`（中间态读数——其价值在生成器，不在本体）
- `X-DUPE`（重复副本——传之即增冗余）
- `X-SNAP`（快照与拉回副本——远端已有或将有其身，传之即重复）
- **状态限**：在途件（`G0`）暂不上传
- **面限**：**归档区全体件不上传**（PI 13:54 之归档区定义 ＋ 令三之冻结旨）
⇒ **通则一句话**：**凡「工作过程之留痕」「他处已有之副本」「未定其性质者」，一律不上传。**

**② 必上传（8 类）**
- `V-KD`／`V-VERDICT`／`V-JUDGE`（判定面——PI 落账之面，远端须可审计）
- `S-SRC`（可复算之基座——无生成器则读数不可复算）
- `R-FINAL`（终版读数——判定之凭据）
- `T-STRUCT`（仓库结构件——公开仓之骨架）
- `D-PAPER`／`D-LETTER`／`D-README`（交付正本与说明）
