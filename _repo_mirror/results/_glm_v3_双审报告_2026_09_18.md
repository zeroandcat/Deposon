## 2. 阻塞问题（Blocking）

### 【阻塞 1】预登记口径与实际判死线不一致——"判死线先行冻结"承诺不成立

**这是全文方法论的基石，必须解决。**

**事实（审稿方独立复算，非推测）**：

| 证据 | 内容 | 时间戳 |
|---|---|---|
| P-L v3 任务 spec | `results/_v3x_p_l_v3_external_spec_2026_09_17.md` | **2026-09-17 11:03:24** |
| 该 spec 的预登记阈值 | **只有 Spearman**：`<0.95` 假设成立 / `[0.95,1.0)` 部分破单 / `=1.0` 同序单调 | 同上 |
| 该 spec 中 `Q` / `0.15` / `R²` / `0.9` | `Q` 出现 6 次（均指 JSON 字段名）；**`0.15` 出现 0 次；`R2`/`R^2` 出现 0 次** | 同上 |
| Phase 1 实际判死线 | `R²=0.7447 < 0.9 → FAIL`；`Q=0.1929 > 0.15 → FAIL` | 报告 09-17 13:35 |

**矛盾**：
1. 稿子 §3.1 声称"阈值与判定规则写入 SPEC"。但 Phase 1 实际使用的 **R²≥0.9 与 Q>0.15 两条判死线，在 P-L v3 的 external spec 里根本不存在**。它们出自 GLM/Trae 提案的"预期"栏（Phase 1 报告 §5.1 自承），不是 Coze worker 的预登记判死线。
2. 该 spec 起草于 **09-17 11:03**，Phase 1 数据产生于 **09-17 11:52**，Phase 1 报告成文 **09-17 13:35**。全部发生在 **D6**。稿子标注 D0=09-11，但 P-L v3 全链路都在 D6——**"判死线在数据产生前冻结"在时间上不成立**。
3. 更严重：P-L v3 的**方案本身**是在看到 P-L v2 的 Spearman≡1 / R²=1 伪影后才"四通道合并"出来的（稿子 §5.1 自述）。**诊断 v2 的通道，又设计了 v3 的判死线，再宣判 v3**——设计与裁判未隔离。

### 【阻塞 2】判定层关键统计量无定义，冻结 SPEC 无法被第三方执行

**Q、β、T/R/A、D_fix2、dpath、BOSS 三层判据——全文零定义**：
- `Q=0.1929`：Q 的定义、归一化方式、主曲线拟合式、缺测规则，全文未给。第三方拿到同一脚本也无法判断脚本是否实现了声称的 SPEC。
- `β`：稿子自承为"cell-level **代理**斜率"，但回归式（因变量、自变量、误差结构、是否加权、n_boot 种子）全无。
- `T/R/A`：三者是实验的核心分类标签，但分类函数（阈值、边界、缺测归属）从未给出。
- `R²=0.1986/0.2670`：稿子称"双口径"，但**哪两种口径**未定义。

**"可审计性 = 第三方可复算"是本文的核心卖点**，但判定函数不闭式给出，这个卖点不成立。

**要求**：把四条路径 + P-L 三态的判定函数写成闭式（输入字段、公式、不等式、缺测规则）；附录给 1 个 cell 的手算工作例。

### 【阻塞 3】"零 LLM 判定调用"与"经裁决"互相否证

- 稿子 §3.1 声称"判定层 LLM 调用次数为 0""事后不得为新数据调整阈值"。
- 但 §4.3 出现 `PARTIAL_PASS（经裁决接受）`、`判死线未全过，经裁决按部分通过接受`；§4.5 出现 `按裁决……暂不定位进 V4`。

**二者只能有一个为真**：
- 若 `PARTIAL_PASS` 不是冻结函数的值域元素 → D7 拍板是**事后人工改写**；
- 若它是值域元素 → "未全过 + 经裁决接受"是叠床架屋，说明函数已失败后另开旁路。

两种情形都**违反 closed 档**。`P-G` 的议程去留同样不是 SPEC 输出。

**要求**：删除一切"经裁决"。只允许输出 SPEC 值域内标签；若函数无 `PARTIAL_PASS`，P-E 必须改记 `FAIL` 或按预登记的部分通过规则重跑，并提交函数源码哈希与复跑 log。

## 3. Major 问题

### A 线（内容 / 方法论 / 学术规范）

**M-A1｜"540 账目守恒"高度疑似恒真式伪影，与本文批判的 P-L v2 同构。**
审稿方复算：`v3_540_conservation_check` 给出 `T540=384 / R540=78 / A540=78 / residual=0`。若 T/R/A 是互斥穷尽标签，残差为 0 **由构造保证**，9/9 残差为零无信息量。这与本文 §5.1 把 `Spearman=1` 定性为"代数恒等式伪影"在逻辑上同构——只是换了统计量。P-F 的 `45/45（T=41,R=0,A=4）` 同理。
→ **要求**：给出 T/R/A 的独立计算路径与容差，证明其不是分类计数恒等式；否则从 P-A/P-F 的 PASS 证据中删除"守恒"字样。

**M-A2｜"跨主干 β 置信区间重叠 = PASS"是统计推断误用。**
CI 重叠 ≠ 参数无差异（经典反例 Schenker & Gentleman）。证明"无差异"需要**等价性检验（TOST）**，而非区间重叠的目视检查。且稿子给出的开源三区间（`[-0.0262,+0.0080]` / `[-0.0369,+0.0001]` / `[-0.0315,-0.0033]`）中，mistral 整段为负、glm53 含 0——**连"是否异于 0"都不一致，却因两两重叠判 PASS**。更甚者，β 若近 0，统计含义是"效应不存在"，与 P1 尺寸缩放 FAIL 同向，**不是独立的稳健性证据**。
→ **要求**：废止 overlap 判据，改用预登记等价性检验或预先指定的 β 差异容差。

**M-A3｜分母口径混用（3/3 vs 3/5 vs 22 vs 60 vs 30 vs 5 vs 9）。**
同一"跨主干稳健"主张，摘要先写"3/3 PASS"、后写"3/5"；预登记主跑分母是 5，完成 3/5，PASS 却改写为"完成子集的 3/3"；闭源 3/3 标明"加速器 v2 **补跑**"，属路径购物（path shopping）。`22`（BOSS 分母）与 `60` 的包含关系未定义；`51/60` 在 9 模型下的聚合方式未定义；`11+2+1+2+1=17` 把 `PASS_for_death`（限定 PASS）计入 11（无修饰 PASS）。
→ **要求**：给一张"宇宙定义表"（每个分数的抽样框、包含/排除、聚合函数）；跨主干只允许一个主分母（5），按 ITT 原则把 INCOMPLETE/UNAVAILABLE 计入分母，补跑最多进敏感性分析；17 项拆成"无修饰 PASS"与"限定 PASS"。

**M-A4｜P-C 的"dpath 8/9 通过"缺预登记锚定。**
P-C 的预登记 SPEC 锚定的是**幂律**主张的判死线；幂律 FAIL_H0 后，"两相划分下 dpath 8/9 通过"作为"派生方向保留"。但两相划分标准、8/9 的分界线是否在 SPEC 中预登记？若是看到 dpath 表现后才划线，属探索性发现，不可与预登记判定并列。
→ **要求**：核查 KT_C1 SPEC 是否含 dpath 判据；若无，标注为 consistency/探索性，从 closed 档映射移除。

**M-A5｜P-F 的"6 次新建 LLM 调用"与"0 LLM 判定"边界仅靠分层修辞切开。**
§4.4 自述"生成层含 6 次新建 LLM 调用"。若这 6 次为计划外补跑，则 45 cells 中部分数据的生成不可复现，P-F 的 closed 档资格存疑。
→ **要求**：说明 6 次调用是计划内重生成还是计划外补跑；如为计划外，P-F 降级为 consistency 档或在 Limitations 声明生成不可复现。

**M-A6｜§6 DAS-2M 基础设施评估与主线关系薄弱，且自相矛盾。**
该节约占全文 1/10，评估一个"0-LLM 文献检索基础设施"，但本文既不生成综述、也不依赖 DAS 检索（文献来自已核验的综述池）。末句"方法学同构"的桥接牵强。且该节自述对 DAS 正文"未逐页核验"，却把"方法学同构"写进本文——与本文自身的 L3 立场冲突。
→ **要求**：大幅压缩该节，或明确本文对 DAS 的依赖关系；删除"同构"句。

### B 线（技术 / 可复算性）

**M-B1｜资产层"第三方可复算"在论文粒度上不成立。**
(i) `SHA-12 = 48 bit`，达不到公开内容寻址标准（满长 SHA-256/BLAKE3），截断后无法在公共哈希空间抗替换，也不能从本文取回对象。
(ii) merkle 只给 12 hex，无叶哈希、无树序、无算法名规范引用。
(iii) `21/21` 含 **5 个"种子占位锚"**——占位符自匹配是恒真，不得计入 schema MATCH（审稿方已确认 `_v3x_frozen_schema_v1.json` 中存在 placeholder/seed 项）。
(iv) `dual_24bit` 22/22 = **24 bit 指纹**，只证明"与自己的记录一致"，不证明 caption→指纹可被第三方重算。审稿方复算确认其口径为 `cap_sha[:6]+cap_sha[6:12]` 纯截断。
(v) §9 是 AI 披露，不是数据可用性声明；无 URL、无满长哈希、无 SPEC 原文。
→ **要求**：公布满长哈希、叶列表、判定脚本、冻结 JSON；`21/21` 重计时剔除占位锚；24 bit 方案废止，改满长双哈希。在此之前收回"第三方可复算""资产层零触动可机读验证"表述。

**M-B2｜"零触动"语义过强。**
锚的哈希未变，只证明**锚的完整性**，不等于"资产层零触动"。零触动要求资产未被读写、修改、或用作数据源。仅凭 D7 复验哈希一致性，无法区分"从未触动"与"触动了但改回去了"。
→ **要求**：改为"锚一致性验证通过"或"内容寻址完整性保持"，或补文件系统元数据审计证据。

**M-B3｜ρ_H,vs,E = 1.0000 未排除下一例代数恒等式。**
审稿方复算 P-G V0.1 报告：`spearman_rho_H_vs_E = 1.0000`，报告自己的解释是"**双曲距离保持欧几里得距离的秩关系（完美排序）**"——这正是对"保序/单调变换"的描述。v2 的教训是"1.0000 先当伪影排查"。放大比 4.4–8.0 与 ρ=1 同时成立，更像单调变换而非几何发现。
→ **要求**：给出 d_H、d_E 公式与反例（打乱嵌入后 ρ 是否仍为 1）；若打乱仍为 1，整条 P-G 降为 UNVERIFIED。

**M-B4｜DAS-2M 主数字不可复算，检索主张超过证据。**
`1,471,166`、`precision@20` 均值 `0.575`、Q4=`0.10`、`52` 条、`15/15`、`55.9%`、`32%` 模板——Q1–Q6 查询串未给，precision@20 无法复算；`15/15` 是从 52 条再抽 15 条，不是 52 条无幻觉；`32%` 无标注规程；"方法论域"先错配后改口径再撤销，说明该精度是事后可调的。
→ **要求**：列出 6 条查询、标注协议、全 52 条核验表；可用性改为"工具探路，consistency 档"。
