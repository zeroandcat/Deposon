## §0 一句话结论

日志爆仓**非偶发**，乃**无保留策略**之必然：6 日实测累计 **19,611 MB**（日均 3,27 MB／峰值 7,067 MB）。本策略定 **「双阈值 ＋ 双日窗口 ＋ 可恢复删除」**：软阈 **6 GB** 触发、清理至 **4 GB**；硬阈 **10 GB** 立即触发；**保留最近 2 个日历日**，今日卷恒不删。⇒ 🔑 **关键设计**：只要常态占用 ≤ 4–6 GB，回收站（上限 10 GB）**永不溢出** ⇒ 可恢复通道得以保持，**不再出现静默永久删**。

## §2 策略正文

### §2-1 面 A · `…\MiniMax\logs`（须经 **D: 实体路径**）

| **参数** | **取值** | **理由** |
| :-- | :-- | :-- |
| **软阈值（触发清理）** | **6 GB** | 日均 3.27 GB ⇒ 约两日即触；留 2 日余量 |
| **清理目标（收敛至）** | **4 GB** | 滞回带，防抖动 |
| **硬阈值（立即触发）** | **10 GB** | 逼近回收站上限（10,240 MB），越此必溢站 |
| **滚动窗口** | **保留最近 2 个日历日**（含今日） | 诊断需近 24–48 h；更早无稽核价值 |
| **删除动作** | 🔴 **可恢复删除**（`rm --` 字面前斜杠路径 → `mavis-trash`） | **⛔ 0 截断／0 `SetLength(0)`／0 `Remove-Item`** |
| **排序准则** | 按**日**（文件名内日期）由旧至新 | —— |
| **频次** | 每日一次（建议 **09:30**）＋ 超阈即时补跑 | 09:30 时前一日卷已封、当日卷在写 |

### §2-2 面 A 之**硬保护**（⛔ 任何情形不删）

① `*-<今日>.log`（应用持句柄）｜② `truncate-*.ps1` 等**非日卷**件｜③ 任何**无法解析出日期**之件（列入未决）｜④ 当前写入中（mtime 距今 < 5 分钟）之件。

### §2-3 面 B · `…\v2\observability\logs`

| **参数** | **取值** |
| :-- | :-- |
| 窗口 | **保留最近 24 小时**（整点卷 ⇒ 约 24×2 件） |
| 上限 | **1 GB** |

### §2-4 面 C · `%TEMP%`（日常）

| **参数** | **取值** |
| :-- | :-- |
| 频次 | **每周一次** |
| 对象 | 安装包（`*.exe`）／安装日志（`Setup Log *.txt`）／`MSI*.tmp` 等，**mtime > 7 日** |
| 动作 | 可恢复删除；⛔ 0 动近 24 h 之件、⛔ 0 动会话／deposon 相关 |

## §3 🔑 为何此策略**保住可恢复性**

| **事实** | **推论** |
| :-- | :-- |
| 回收站上限实测 2,048／5,092／**10,240 MB** | 站内常态占用须 **≪ 10 GB** |
| 本策略常态占用 **4–6 GB** | 🔑 **站内永不溢出** ⇒ **不再触发 Windows 永久清除最旧项** |
| 前次事故 | %TEMP% 清理时 1,568.78 MB（91%）因**超站容**被静默永久删 —— 本策略以**上限先于删除**从根上避免 |

⇒ 📌 **「先设上限、后删旧卷」是本策略之核心**；若先删后限，回收站仍会溢。
