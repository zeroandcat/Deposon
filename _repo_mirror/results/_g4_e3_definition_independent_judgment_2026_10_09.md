## §3 理由（三条主线 · 逐条可驳）

### §3.1 主线一 · 判别力充足性：E3 是**因变量面**，二分支已是最小充分编码

| 环节 | 内容 |
|---|---|
| claim 结构 | C‑G4（`b1c7c24926bb` §1.2）：「两会话 skill 读**结果不同**，差异可由 **E1 或 E2** 之一解释」 |
| 四面分工 | **E3＝因变量（结果面 outcome）**；E1／E2＝自变量（解释面）；E4＝控制面（核「同写法」字面成立） |
| G4 现象形态 | 「同写法、同实体、同日，两会话结果相反」⇒ 结果面的**判别需求＝「读到／没读到」是否相反** |
| `execute` 出口编码 | `details.found: true` ／ `details.found: false` ⇒ **恰为该判别需求的最小充分编码** |
| 态②是否携带增量 | 态②（ambiguous 报错）经 `9196a608bb0d` C5‑e 已判：「歧义是**抛错**、**不是** not found，**与 G4 的现象形态不同**」；且本机歧义集**恒空**（料件 §2.2‑⑦，7/7 agent 根域无 `skills/`）⇒ **态②在本机构造域内取值数恒为 0** |
| ⇒ 结论 | 三态中的态②对 claim C‑G4 **零判别增量**；保三态＝**为一个在本机不可造的态支付改造成本** |

### §3.2 主线二 · 构造非退化：B 触发「码本坍缩」，A 不触发

## §4 反方意见（本件结论的最强反驳 · 逐条列明并回应）

### §4.1 反方 R1（**最强反驳**）：A 压平了 Δ6 的语义差，会**看不见** G4 的真实机制

**反驳**：料件 §2.2‑⑥ 新发现——内层 `readRegistrySkillByName` 返回 `undefined` 之后，`readNativeSkill` **还有一层 desktop 兜底**。⇒ 内层 `undefined` **⏏** 工具侧 `found:false`。若 G4 的真实机制恰是「内层因 E1 白名单丢弃 → 但 desktop 兜底救回」，则**两会话的 `execute` 出口都是 `found:true`，而内层行为相反** ⇒ **A 的二分支记法对此完全不可见** ⇒ A 会让「内层差异」这一**正是 E1/E2 想要暴露的信号**从结果面上消失 ⇒ **A 恰恰在 G4 最需要辨别的场景下失明**。

**评估**：⚠️ **本反驳成立，且是 A 的真实盲点。** A 保留的是「用户侧最终可见形态」，B 保留的是「内层判定形态」——两者**不是同一物的两种写法**，是**不同观测面**。

**回应（不驳倒，而是收窄 A 的适用边界）**：
1. **A 的定义必须写死为「用户侧出口形态」**，⛔ 不得声称它测到了「内层判定结果」。料件 §5 末行已称 A「变为用户侧实际可见形态」⇒ 此点**料件已正确表述**，本件予以确认并**加码为定义稿的强制字面**。
2. **Δ6 的盲点不由「择 A」造成，而由「E1 打点独立于 E3」兜住**——E1 的打点位是 `readRegistrySkillByName` **入口**（设计件 §2／登记件 §5.2），**本就在内层** ⇒ 内层差异由 **E1 面**记录，**不依赖 E3**。⇒ R1 的实质是「E3 单面失明」，而**四面合起来不失明**。
3. ⇒ **本件不改主结论**，但**加一条强制条件（见 §6‑C2）**：A 方案下，**E3 面的解释权必须与 E1 面绑定叙述**——⛔ 禁以 E3 单面结论推断「内层判定相同」。这是**口径约束**，非定义修改。

### §4.2 反方 R2：A‑1 的双轨要求 try/catch，会**改变异常传播路径**，成本被料件低估

**反驳**：料件称 `execute` **无 try/catch**，A‑1 需「包一层 try/catch 记异常支路」⇒ 即便 `catch` 后**原样 rethrow**（语义等价），仍是对**核心读路径异常传播**的侵入，**且异常语义一旦写错（吞掉／改包装／漏 rethrow）会静默改变行为** ⇒ 「自包含块 ⇒ 可按块摘除」的回退优势**部分抵消**。

**评估**：⚠️ **部分成立。** try/catch 的正确写法（`catch (e) { record(e); throw e; }`）语义等价，但**「打点自身正确性先验不可证」**（设计件 §3.1 风险④）在 A‑1 下**放大**——错误写法不会立刻暴露。
