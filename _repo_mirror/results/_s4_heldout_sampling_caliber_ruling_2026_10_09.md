### §3.2 R2 · **RNG 实现与流式**

| 项 | 内容 |
|---|---|
| **✅ 推荐** | **① `np.random.RandomState(42)`（legacy MT19937）· 全局单流 · 非逐格重播** |
| **理由①（R2 之实质是「家族」，非仅「流式」）** | **`TH-v3-15` 仅写「seed ＝ 42」、未写 RNG 家族**。本棒实测**同 seed 之下三家族产出互异置换**（`permutation(10)`）——`np.random.RandomState(42)` → `[8,1,5,0,7,2,9,4,3,6]`；`np.random.default_rng(42)`（PCG64）→ `[5,6,0,7,3,2,4,9,1,8]`；`random.Random(42)` → `[7,3,2,8,5,6,9,4,0,1]` ⇒ **只钉 seed 不足以复现** ⇒ R2 须钉「家族 ＋ 流式」两层 |
| **理由②（沿既有实现面 ＋ 跨版本稳定）** | 盘上唯一既有抽样器之签名即 `rng: np.random.RandomState`（`8a81d90c69ba` **L889**）⇒ 选 legacy `RandomState` 与既有实现**同族**；且 numpy 对 legacy `RandomState` 之流有**跨版本稳定承诺** ⇒ 未来 numpy 升级后 26 件**仍可复现**（`default_rng`／PCG64 **无同等待遇**） |
| **理由③（排除 ② 逐格派生 seed）** | `RandomState(42 + 格号)` **构成派生 seed**，与执行棒已核得之要素①处置「**⛔ 0 换、0 加偏移、0 派生 seed**」（`2a2ad5c2e29f` §2.1 ①）**直接冲突**；且引入**隐藏参数「格号」之四解**（0 基／1 基／仅贡献格序／全 128 格序）⇒ 双重歧义 |
| **理由④（R2 与 R4 耦合）** | 全局单流 ⇒ **R4 之消耗顺序成为承重参数**（顺序变 ⇒ 每格取件变）⇒ **R2 与 R4 须同裁、不可分裁** |
| **替代案** | ② 逐格派生 seed（⛔ 冲突纪律，理由③）｜③ `np.random.default_rng(42)`（⚠ 结果合法且跨版本稳定承诺弱于 legacy，**非不合法** —— 若 PI 择之，本件其余各项仍全数成立，⛔ 0 与 ① 混用） |

### §3.3 R3 · **取法**

| 项 | 内容 |
|---|---|
| **✅ 推荐** | **① `rng.shuffle(候选表)`（作用于 R1 序之完整候选表，长度 n）→ 取 shuffle 后之前 k 件**；留出集**按集合认定**（⛔ 0 以 shuffle 内序为落面序） |
| **理由①（沿既有动作同形）** | 既有实现之取件动作即 `rng.shuffle(...)` → 切片（`8a81d90c69ba` **L897–901**）⇒ 本项与既有实现**同形**，差异仅在「分层轴」与「取量规则」两处（T-5 所禁者），⇒ **不合规点被压缩至最小面**，便于审计「T-5 之禁已被遵守」 |
| **理由②（排除 ③ 确定性哈希排序）** | 哈希序将使 **`TH-v3-15` 之 seed 42 沦为装饰**（对结果 0 影响）⇒ 与冻结字面「seed ＝ 42」之**用意相悖**（该阈值之全部意义 ＝ 使留出具随机性且可复现），且「随机留出」退化为「确定性截断」 |
| **理由③（排除 `random.sample` / `choice` 之含糊写法）** | `random.sample` 属 stdlib 家族 ⇒ 与 R2 ① 不同流（**违反 R2**）；`choice(..., replace=False)` 在本环境（numpy 2.5.3）实测与 `shuffle()[:k]` 于 n∈{4,5,6,7,9,10,13,16} 各 k 下 **0 分歧**，但此为**实现事实、非契约保证** ⇒ 规格须钉**具体调用**，⛔ 0 只写「抽样」二字 |
| **理由④（集合认定 ＋ 落面另定）** | shuffle 后前 k 之**内序**无判读意义（留出集之语义是「哪些件被留出」）⇒ 以**集合**认定可吸收「同集合不同内序」之实现差；落面排序另由 R1 键规定（§5.6）⇒ **0 引入第二处自由度** |
| **替代案** | ② `rng.choice(候选, k, replace=False)`（⚠ 本环境等价、**非契约**）｜③ 确定性哈希排序（⛔ 0 成立，理由②）｜④ `rng.permutation(候选)[:k]`（本环境实测与 `shuffle` 同值） |
| **风险** | 若未来 numpy 之 `choice` 与 `shuffle` 分叉 ⇒ 以**本项钉死调用**消解；⛔ 0 在实现中「就近改用等價写法」 |

### §3.4 R4 · **跨格 RNG 消耗顺序**

| 项 | 内容 |
|---|---|
| **✅ 推荐** | **① 格序 `b → s → o` 三键升序（`b` 外层、`s` 中层、`o` 内层，各 0–7 / 0–1）；且 ⭐ 仅 `floor ≥ 1` 之 16 格消耗 RNG —— `floor = 0` 之 38 个占格与 74 个空格，消耗 0 次抽取（⛔ 0 对其调用 `shuffle`）** |
| **理由①（沿既有登记面）** | 帧件 `8dfc9e0d8bf9` 之 `cells` 数组**已为 `b→s→o` 升序**（本棒实测 128 格**序破 0 处**）⇒ 采用本项即使帧件 `cells` **原地即消耗序**，0 重排 |
| **理由②（承重性）** | 全局单流（R2 ①）⇒ **消耗顺序即结果的一部分** ⇒ 须钉；「按 `n` 降序」「按贡献量降序」等序**无冻结字面支撑**，且**引入数据依赖之隐判据**（数据变 ⇒ 序变 ⇒ 结果变）⇒ ⛔ 0 采用 |
| **理由③（⭐ 本件新增补钉 —— 执行棒 R1–R4 未列之隐参数）** | **`floor = 0` 之格是否消耗 RNG，从未在任何冻结面被规定。** 若实现对其调用 `shuffle`（哪怕取 0 件），将**推移后续格之流** ⇒ **26 件变**而**表面无任何违规**。本件**显式裁定：`k = 0 ⇒ 0 次抽取`**。理由：0 贡献之抽取无谓；最小化流消耗面；且该裁定**不违任何冻结字面**（`T-5` 只禁 `round()`，未禁 0 消耗） |
| **理由④（0 空训练格）** | `floor(0.30·n) ≤ n − 1` 对 `n ≥ 1` 恒真 ⇒ 每贡献格**必留 ≥1 件**；实测各贡献格保留件数**最小 ＝ 3** ⇒ **0 空训练格**风险（留出语义安全） |
| **替代案** | ② 其他格序（按 `n` 降序／按文件首次出现序／随机格序）—— ⛔ **0 冻结字面支撑**；③ `k=0` 之格**亦消耗** RNG（⚠ 合法但无谓，且使「贡献格集合」变更时全体漂移面扩大） |
| **风险** | 若未来域变动致**贡献格集合变动** ⇒ 消耗序自动变动 —— **但规格仍自洽**，因格序由 `b→s→o` **定义**而非由数据**择取** ⇒ 此为规格之**优点**（非风险面） |
