## §2 候选面之界分（**各出结论＋理由＋反方**）

### §2-1 候选甲 ｜ `None` 哨兵

**结论**：**可行但非最优**——建议**不采**（理由见 §2-1-2 之轴②实测劣势）。

**理由（三条 · 逐条挂证据）**

1. ✅ **比较面 fail-loud**（§4-1 实测）：4 路径中 3 路 `TypeError` ⇒ ⛔ 0 静默产出 `PASS_H1`／`GRAY`，符合 v1 `L169`「⛔ 0 注入 `0.0`」之戒之精神。
2. ✅ **0 新造词**：`None` 为 Python 内建 ⇒ **代码面 0 新造术语**，且 v1 `L169` 之戒语**已逐字列 `None`**（虽列于禁侧）。
3. ✅ **原生世界 type 可分**（§4-2 M4 更正实测）：`isinstance(x, float)` 即可将其与真实率分离，**⛔ 0 依赖消费方读字符串**。

**反方（最强于甲者 · 本棒如实列出）**

- 🔴 **轴②之实测劣**：于**最常见之疏忽惯用法**下即静默坍为数值——`None or 0.0` ⇒ `0.0`（**实测**）；JSON `null` 经数值工具链化为 `NaN` ⇒ `nan >= 0.3` 与 `nan <= 0.1` **皆 `False` 且不抛错**（**实测**）⇒ **静默满足全部比较**。**此二径正是退役登记件 `1ba41ba3bbe9` §2-1 与 v1 `L169` 所禁之同一失效模式**（未测被读作「0 cell 超理论界」）——**择 `None` 等于把该失效模式之触发条件交予消费方之疏忽**，而择 `inactive` 则**以缺省免疫之**。
- ⚠ **字面相邻性**：v1 `L169` 逐字「⛔ **0 注入 `None` 当作有效值**」⇒ 择 `None` 使**承载面与戒面正面相邻**，其后任一实施者须反复辨析「占位之 `None`」与「有效值之 `None`」；择 `inactive` 则**完全回避该相邻**。
- ⚠ **`bool(None) == False`** 与 `bool(0.0) == False` **同值**（**实测**）⇒ 在任何 truthiness 分支上，`None` **不可区分于**被禁之 `0.0`。

### §2-2 候选乙 ｜ `inactive` 字符串

**结论**：**推荐采之**（附 §5 之三项限定条件）。

**理由（五条 · 逐条挂证据）**

1. ✅ **比较面 fail-loud 且不劣于 `None`**（§4-1 实测逐格相同）⇒ 择之**不损失任何机械安全度**。
2. ✅✅ **轴②之缺省免疫**（本件之**决定性**理由）：`'inactive' or 0.0` ＝ `'inactive'`（**实测**）；字符串 **⛔ 不被 `NaN` 化** ⇒ 于 `or`-惯用法与 JSON-数值工具链**皆静默免疫**。**即：择之者，安全性由载体本身提供，⛔ 0 依赖消费方加守卫。**
3. ✅ **回避 v1 `L169` 之字面相邻**：`inactive` 非 `0.0` 亦非 `None` ⇒ **不触该戒**，且无须 PI 事后重新诠释其字面。
4. ✅ **登记面 0 新造词**：退役登记件 `1ba41ba3bbe9` §2-1 逐字已以「**inactive**」为**该面之状态词**（「值面状态 ＝ **inactive**」）⇒ 择之**复用既有已登记之术语**（⚠ 代码面仍为新字面量——此差别见 §6 之限定②）。
5. ✅ **仓内既有先例**：仓内已有**字符串承载「未算出」**之先例——`scripts/run_v3x_finalize.py`（`46787531bf8e`）`:65`／`:81` 逐字 `'source': 'NOT_RUN (model hung on prior cells)'` ⇒ **非生造体例**。

**反方（最强于乙者）**

- 🔴 **轴③之实测劣 · 即本件之最强反方**：`str` **类型上不可区分于字符串化之真实率**（§4-2 M4 更正实测：字符串化世界里 `'0.6667'` 与 `'inactive'` **同 type**）⇒ **type check 失效**，须**值检查**；若消费方（或报告层）曾将率字符串化，则 `inactive` **同域混同**。
- ⚠ **同名词（homonym）风险**：`inactive` 于**退役件中系登记面之中文态词**，被引入**代码面**后，其语义之权威源与登记件是否同一，**须 PI 确认**（本件新立 `KD-C14-2`）。
- ⚠ **`sorted`／`set` 面**：字符串载与数值混列时 `sorted` **抛 `TypeError`**（**实测**）⇒ 虽属「响亮失败」，然其**响亮度弱于**专用类型之被 type-system 拦截。

### §2-3 候选丙 ｜ 专用哨兵类型／单例（本棒归纳之第三径）

**结论**：**机械面双胜 · 治理面最重**——**不建议采之**，但**如实登记其机械优势为三候选之最**。

**理由（三条）**

1. ✅✅ **机械面同时占优轴②与轴③**：类型相异 ⇒ 既**不坍为 `0.0`**（优于甲）又**type check 可分**（优于乙）；且可同体承载「态＋因」。
2. 🔴 **⚠ 治理面代价一（宿主问题）**：K-D-14 逐字「⛔ **0 改 calculator 任一字节**」⇒ 专用类型**⛔ 0 得定义于 `distortion_calculator.py`** ⇒ 须落于**另一新件** ⇒ 引入一个**非五锚之内**之导入依赖（冻结五锚见 spec `:10`）。
3. 🔴 **⚠ 治理面代价二（一域一面之冲撞）**：v1 `L169` 逐字已立**元参 `U_axis_state` ＝ {`DISABLED`（`null-U`）, `REGISTERED_ONLY`（`U-戊`）, `ACTIVE`}** 为**「判死面 v1 之实参供给状态须以元参登记」**之指定面 ⇒ 另立专用载体有构成**第二套态词汇**之风险（**⛔ 0 与元参互代**）。

**反方（最强于丙者 · 亦本件推荐之主要阻力）**

- 🔴 **「大材小用」**：为**单一 `null-U` 面**（15 格中之被剔子集）新建一个类型＋一个新件＋一条导入依赖，**其治理成本大于其机械收益**——**因其机械收益仅在「消费方已正确 type check」时兑现，而本仓并无任何 `isinstance` 守卫之既存纪律**（§4-2 M4 之更正实测显示该守卫**须由消费方自建**）。
- ⚠ **⛔ 0 与 v1 `L169` 之元参构第二词汇**（§2-3 之 3）⇒ 反而**新增**一处「态在何处」之歧义，与聚合规则之 `U_axis_state` 必随报面**争夺**同一职责。
