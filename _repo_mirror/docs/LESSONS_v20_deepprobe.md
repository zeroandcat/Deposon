## A. 文档-数据一致性（本批最大病灶，三次中镖后的总清算）

### #19 斩杀线类表述禁止手写——这是第三次中镖
- **事实**：冻结结果 JSON `H_A_dead.triggered=true`（预登记规则 ≥3 反转判死，实 3→4 反转），
  Findings 却手写「未触发（反转图<3）」，且「16/20」与 JSON 的 15+/3−/2= 不符。
  此前已有 Table C1 手改事故（v1.9）、kill_lines 漏检（v12 之前无任何 verifier 检查该字段）。
- **教训**：凡「由数据机械求值」的判定（斩杀线、Holm、逐图违规清单），
  文档引用时**必须给出 JSON 字段路径**，verifier 必须强制对照；
  人手写转述一次，就有一次漂移机会。
- **防线**：v21 强制对照 Findings 文案与 JSON 值；
  `docs/SPEC_v2.0_amendment1.md` 新规——Findings 数字必须可追溯到结果 JSON 具体字段。

### #20 显著性头条的口径必须随语料生长重估
- **事实**：H-A1 符号检验 p 值在 16 图（0.0075）→ 22 图（0.0118）→ 族代表/主档子集
  （0.031–0.29，多种取法不过 0.05）之间漂移；「全独立口径失守」而 H-A2 跨口径稳健。
- **教训**：样本量是**图**不是边；图间相关性（同族扫描图）使名义 n 虚高。
  头条结论应以最保守口径（族代表集 + Holm）为准，其余口径作为灵敏度如实报告。
- **防线**：C1 更正后存活主张收缩为「degree 稳健 + 高 hub 局部优势」；
  语料变更触发既有统计的强制重跑（v18 已改 ≥ 下界断言）。

## B. 实验设计

### #21 选择题臂的候选集必须全部来自图节点，否则难度不可比
- **事实**：题库陷阱项 2/4 不是图节点 ⇒ 先验/场臂对其机械 −inf ⇒
  39/40 题退化为 2 选 1（机会 50%），1 题白送；「先验 92.5% = CoT 92.5%」由此垮塌，
  真实可比口径（开放 top-1）是 67.5% vs 92.5%，差 25 点。
- **教训**：跨臂比较前先审计**每个臂的有效候选集大小分布**；
  有效 k 选 1 的机会水平 1/k 必须作为该臂的基线写进结果 JSON。
- **防线**：C2 撤回 + 开放候选重测入库；修正案要求题库构建器校验「全部选项 ∈ 图节点」。

### #22 近零得分臂是「伪装随机臂」，必须先做零信号检测
- **事实**：tfidf 在族 S 上余弦近全零（S4 金边 >0 仅 0/58、S5 1/7），
  排序实际由 1e-9×rng tiebreak 抽签决定；S5「胜场」在 37.5% 的抽签中复现。
  单抽无方差设计让它以「语义臂击败场」的形态进入 BOSS 清单。
- **教训**：任何「X 击败场」事件，先问 X 在该图上是否输出非退化信号
  （非零得分占比、标签置换基线、tiebreak 敏感性）。
- **防线**：BOSS 门槛 margin≥3 金边（6 事件保留 / 4 事件降级为抽签候选）；
  修正案要求语义臂报方差、中文短标签弃用 3-gram。

### #23 单位换算是静默杀手：注释声称的换算要当代码审
- **事实**：光子模块 `nep_floor = 10*nep_pw*1e-3` 注释称「pW→mW」，实为 ×1e-9；
  下限从 10 pW 变 10 nW（严 10⁶ 倍），预算 80dB→20dB，「14 跳规则」其实是
  单位 bug 与 max_hops=10 截断叠加的产物。更正后真值 18/22、≈27 跳。
- **教训**：物理量换算行逐一写下量纲推导；「巧合的整数阈值」是首要怀疑对象。
- **防线**：C4 更正落盘；verifier v20 附 erratum，v21 锚定更正后值。

### #24 截断参数（max_hops、top-k、窗口）必须写进结果 JSON 并参与复现
- **事实**：`min(10, n_named)` 截断 + `nxt[0]` 索引贪心使 S1 真实 19 跳被截 9 跳，
  「最长链近似」名不副实；因单位 bug 掩盖，落盘分类未变——「对的原因错」。
- **教训**：结果对了不代表机制对了；截断/近似参数是协议的一部分。
- **防线**：更正版以真实最长路径复算；参数随 JSON 落盘。

## C. 工程纪律

### #25 事务窗口：「写图」与「建索引」必须原子化
- **事实**：摄入脚本直调 `ingest_domain` 写 corpus 图但从不 `build_index`，
  41 分钟内全部 10 个评估脚本静默漏 2 域（只读 index.json）。
- **教训**：凡存在「写 A 后必须更新 B」的两步操作，B 不做完 A 就不算成功；
  读取方应有孤儿哨兵——发现目录里有未登记资产要**响亮失败**而非静默忽略。
- **防线**：`ingest_domain` 成功写图后立即 `build_index`；
  `load_corpus` 发现 orphan JSON 即 raise（本批已入库）。

### #26 幂等重跑不得擦除账本
- **事实**：v18 结果 JSON `total_http_attempts_actual=0`——幂等重跑把真实
  HTTP 尝试计数自我擦除；34 个缓存 JSON 零 attempt 字段；
  总账 ~53% 消耗（~29 次）无预登记（CoT 9 次 + bigquiz ~20 次）。
- **教训**：缓存命中也要记「本应发生的调用数」；预算账本是预登记的一部分，
  修正案要随 API 使用同步登记，不能事后补账。
- **防线**：修正案 A5 追认登记 + 新规「attempts 必须落盘、禁止幂等擦除」。

### #27 verifier 对散文的硬编码断言是漂移放大器
- **事实**：6 次假 FAIL 全记录——大小写敏感、「162s」运行秒数、字节/字符口径、
  冻结检查读活状态、计数断言（`len(L)==4`、`n_graphs==22`）在语料生长后必然 retroactively 打破。
- **教训**：断言下移到结果 JSON 的**结构字段**；计数一律用下界；
  每版本 anchors.json 单一事实源；冻结检查钉输入快照 sha 而非活文件。
- **防线**：v12/v18 改下界断言；v17/v20 附 erratum（冻结不覆写）+ v21 承接。

### #28 冷启动复现要在干净克隆上实测，且依赖清单不能只靠 MANIFEST
- **事实**：`run_v17_fusion_fix.py` 未推送却被 6 个在库脚本 import，
  `git clone` 后 import 即崩；MANIFEST 里 3 条再生命令是死命令；
  语料 20→22 图后「确定性再生」对快照不成立（p 值随之漂移）。
- **教训**：复现性声明的唯一裁判是干净克隆实跑；
  快照承诺必须钉在 index.json 的 sha 上，而不是钉在目录名上。
- **防线**：断链文件已补推；MANIFEST 加注快照钉版规则；R2/E1 最小补齐集留档。

## D. 深探方法论（本轮验证有效，固化为流程）

### #29 「先复现、后质疑」的探针协议有效，应常态化
- **事实**：R1/R2 均先逐位复现既有文件值（tfidf 臂、H-A1 符号检验、sha256 22/22 一致）
  再提出质疑——9 问 9 实锤，无一误报；且探针工作在 /tmp 副本，仓库零污染。
- **教训**：质疑的成本是复现；不复现的质疑不接受。
  双探针独立撞上同一病灶（C1）是最高置信度信号。
- **防线**：深探轮已写入路线图（每大版本至少一轮 R1 科学线 + R2 工程线）。

### #30 「对的原因错」与「错的原因对」都要记入诚实清单
- **事实**：光子分类结果在单位 bug 下不变（对的结果错的机制）；
  field_mean 的 52.5% 恰是 2 选 1 机会水平（看似信息的噪声）；
  S6 复现锚点 0.4706 逐位匹配但 0.8 阈值来自不同协议口径（对的数字错的判据）。
- **教训**：阴性/阳性结论之外存在第三类风险——**归因错误**。
  每个关键数字要回答：它的机制解释被直接验证过吗？
- **防线**：corrections 文档对四项更正均给出「机制层」证据而非仅数值修正；
  honesty 字段披露口径差异。
