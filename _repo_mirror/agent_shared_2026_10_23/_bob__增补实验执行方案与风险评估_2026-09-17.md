## §1 测法（提案 §3 素材）

### 1.1 可比性不变量（先锚死，再谈设计）

增补实验的唯一目标是给 P-L v2 换真数据（Spearman=1 系同序单调构造，见 `_p_l_real_data_collapse_runner_2026_09_16_v2.py` L64–66 及 Trae 提案 §0 诊断）。因此**换的只能是 backbone，不能换题目、prompt、抽取、判分**——否则新旧数据不可对照，实验就白跑。以下 5 项为不变量，全部锚定到既有 runner 的一手实现：

| # | 不变量 | 锚定来源（一手） |
|---|---|---|
| I1 | 30 道题 = gsm8k_1–15 + stq_1–15，题文与 gold 逐字一致 | `results/deposon_benchmark_v1_4_gsm8k_details.json`（实测 100 题，keys 1–100）＋ `results/deposon_benchmark_v1_4_strategyqa_details.json`（实测 99 题）＋ minimax m3 runner 加载段 L62–164 |
| I2 | prompt 模板：GSM8K `Question: {q}\nAnswer with one number only:`；STQ `Question: {q}\nAnswer with Yes or No only:` | minimax m3 runner L154/L163 原文 |
| I3 | 抽取规则：`extract_number`（加粗 `**N**` 优先→末个数字 token，千分位逗号剥除）；`extract_yesno`（加粗优先→末个 Yes/No token） | minimax m3 runner L118–130（extract_number）与 yesno 对应段 |
| I4 | 判分规则：GSM8K `pred is not None and abs(pred - float(gold)) < 1e-3`；STQ `pred == str(gold).strip().capitalize()` | minimax m3 runner L221–230 原文 |
| I5 | 采样参数：temperature=0.0、max_tokens=1024、timeout=30 s/cell、user 单轮 messages、严格不重试不换模型 | minimax m3 runner 文件头 docstring 与 L69–79 |

> 为什么锚 minimax m3 runner 而不是 9 模型 runner：9 模型 runner 用 max_tokens=2048/timeout=60 s（其 JSON `max_tokens: 2048, timeout_s: 60` 实测），且 5 制品中唯一在仓库内的 30-cell Q&A 制品（minimax 制品）的 `meta.source_data` 直接指向 minimax m3 30cells run JSON。**与 5 制品可比 = 与 minimax m3 runner 链路同构**，这是判基线对照成立的根据。

### 1.2 Runner 流水线四层设计

```
┌─ L0 题源/判分层（0 改动克隆）──────────────────────────┐
│  读两个冻结 benchmark details JSON（只读）             │
│  组 30 cells 元数据（cell_id/task/question/gold/prompt）│
│  extract_number / extract_yesno / 判分阈值逐字照搬      │
├─ L1 API 调用层（backbone 参数化；铁律 1/2/3/5）─────────┤
│  key：runtime Path().read_text() 编码循环→regex→env 注入 │
│  proxy 6 变量清空；sanity 探针 'What is 1+1?'           │
│  urlopen 单轮 chat，30 s fast-fail，超时计错不重试       │
├─ L2 制品构建层（0 LLM 纯 JSON 变换）───────────────────┤
│  run JSON → artifact JSON（schema §1.3）＋三列 hash      │
├─ L3 复算层（0 LLM 纯 hashlib；沿 _verify_15frozen.py）──┤
│  制品三列重算 + 18 frozen 0 触动 + 5 制品 before/after   │
└────────────────────────────────────────────────────────┘
```

**L0（题源/判分层）**：见 §1.1 不变量表，逐字照搬。唯一允许的差异是 `MODEL` 常量换成新 backbone 的 model ID（§1 backbone 选型由阿兰备忘另发，本方案将其参数化为 `<BACKBONE_MODEL_ID>`）。

**L1（API 调用层）**关键约定：

# 每 cell：urlopen(req, timeout=30)，HTTP 200 取 body.choices[0].message.content
#          超时 fast-fail → is_correct=False, note='timeout_30s'（runner L236-245 note 分类照搬）
# 严格模式（runner L4 原文）：no retry / no model switch / no proxy / no OpenRouter(火山通道时)

- **key 安全**（铁律 1/5）：runtime `Path().read_text()` 读 GB18030 key 文件，正则提取后注入 `os.environ`；log 只允许截断式（前 20＋后 4，沿 minimax runner `key_truncated` 惯例与 9 模型 JSON `auth` 字段的写法）；run JSON 的 `auth` 字段沿 9 模型 JSON 文案：`'(key loaded from env at runtime; literal key never written to disk)'`。**检测/自检脚本本身也纳入无 key 扫描**（历史教训：密钥检测规则自身也可能泄漏）。
- **checkpoint（PARTIAL 兜底第一道闸）**：每完成 1 cell 就 append 写 checkpoint JSON（比 9 模型报告 §9 建议的「每 model 一次」更细，因单 backbone 单模型）；checkpoint 文件名含 backbone+attempt 双键，避免秒级时间戳同名覆盖（历史教训 9）。

**L2（制品构建层）**：纯 Python json/hashlib 变换（沿 `_build_minimax_artifact_2026_09_16.py` 全套流程），无任何网络调用——制品 `meta.iron_rules` 中 `no_llm/no_gateway/no_key: true` 声明的就是这一层（minimax 制品 meta 同款五键），与 L1 runner 层的网关调用分属两阶段，互不矛盾。构建自检沿 builder 五项：cells≥20、逐件三列重算、element 零主体标签（`'subject' not in a and '<backbone>' not in str(a)`）、拼接锚 `79f8dfa2c296` 核对、源 run JSON 只读。

**L3（复算层）**：见 §1.4 伪代码。

### 1.4 0 LLM 纯 hashlib 复算层（伪代码）

沿 `_verify_15frozen.py` 模式（sha256[:12] 逐文件＋resolve() repo→archive fallback）＋ builder 自检模式：

```python
# L3 复算层：0 LLM，仅 hashlib + json + os
REPO_BASE, ARCHIVE_BASE = Path(r'_repo_mirror'), Path(r'〔本地资料区〕\_archive_deposon_2026_09_17')

def resolve(rel):                       # 沿 _verify_15frozen.py L14-22
    for base in (REPO_BASE, ARCHIVE_BASE):
        p = base / rel
        if p.exists(): return p, base.name
    return None, 'MISSING'

def sha12_file(p):  return hashlib.sha256(p.read_bytes()).hexdigest()[:12]
def sha12(s):       return hashlib.sha256(s.encode('utf-8')).hexdigest()[:12]
def canonical(obj): return json.dumps(obj, ensure_ascii=False, sort_keys=True, separators=(',',':'))

REL = 'deposon_team/products/<backbone>_artifact_v_2026_09_17.json'
TA  = 'd78c42f7bab4|0ff54f8d2f60|a8f81c98ea8a|bff8b1ce1f8c|d9a6a099b905'
data = json.loads(resolve(REL)[0].read_text(encoding='utf-8'))

# (a) 逐制品三列重算（core 8 字段，不含 artifact_id）
for i, a in enumerate(data['artifacts'], 1):
    core = {k: a[k] for k in ('source_cell','task','question','llm_output',
                              'extracted_answer','is_correct','latency_ms','usage')}
    aid = 'artifact_%03d' % i
    assert sha12(canonical(core)) == a['three_hashes']['content'],  f'{aid} content 漂移'
    assert sha12(REL + '#' + aid)  == a['three_hashes']['path'],    f'{aid} path 漂移'
    assert sha12(TA + '|' + aid + '|' + a['three_hashes']['content']) \
                                      == a['three_hashes']['anchor'], f'{aid} anchor 漂移'

# (b) 文件级三列重算
assert sha12(canonical(data['artifacts'])) == data['three_hashes']['content']
assert sha12(REL)                          == data['three_hashes']['path']
assert sha12(TA + '|' + REL + '|' + data['three_hashes']['content']) == data['three_hashes']['anchor']

# (c) 18 frozen 0 触动核验（16 anchor 路径 + 2 anchor JSON 自身；逐条 sha12 比对，§2.2 完整列表）
for rel, expected, name in FROZEN_16:
    p, src = resolve(rel)
    assert p is not None and sha12_file(p) == expected, f'FROZEN TOUCH: {rel}'

# (d) 5 制品 baseline 只读核验（before == after，逐件 sha12/size）
for name, path, size, sha in PK5:      # PK5 = P-K verify JSON 的 5 行（见 §3 附录 A）
    assert sha12_file(resolve(path)[0]) == sha, f'baseline 制品被触动: {name}'

# (e) 源 run JSON 只读核验（L2 构建前后 sha12 一致）＋题文零改动核验
#     （新制品 question 与 minimax 制品 question 逐 cell sha12 比对，30/30 须全同）

# 结论行（沿 _verify_15frozen.py L62-64 输出风格）：
# 'artifact 3-hash recompute: 30/30 PASS'
# '18 frozen 0-touch declaration: PASS'
# 输出: results/_v3x_d0_5_verify_2026_09_17/<backbone>_verify_2026_09_17.json
```

> 复算耗时量级：同规模 0 LLM verify 在仓库实测为亚秒级（P-K verify 全程 `elapsed_seconds: 0.0157`，P-L v2 runner `elapsed_seconds: 0.0143`），不构成预算压力。

### 1.6 30 cells 起步 → 扩 60 cells 的条件

- **源可得性（已实测）**：gsm8k details 100 题、stq details 99 题（keys 1–100）→ gsm8k_16–30＋stq_16–30 全部在冻结源文件内，只读扩档，0 frozen 触动。
- **触发条件（全部满足才扩）**：
  1. 30-cell run 状态 `COMPLETE` 且 timeout cell ≤ 1（沿 minimax 重测先例容忍度）；
  2. 首轮判读落边缘带：Spearman ∈ [0.95, 1.0)（邀请函 §4 判「需补测」区间）或爱丽丝 §2 检验量分辨力不足（30 cells 并列校正后 CI 过宽）；
  3. 时间余量 ≥ 40 min（不挤占 18:00–22:00 验证写稿段）；
  4. user/Mavis 拍板（铁律 4 节省原则：小规模先验证边际，禁止未经拍板直跑大网格——与「不一次跑 300 cells」同源）。
- **扩档产物**：新 run JSON＋新 `…_60cells…` 制品 v2（60 件，artifact_001–060）；30-cell 制品与 5 制品基线一律不动；对照表升级 60 行。60 档同时是 closeout 报告 §2.4 建议「多尺寸重做（30/45/60/100）」中的落位档。
- **口径不变**：扩档后题文/prompt/抽取/判分仍沿 §1.1 不变量，60-cell 与 30-cell、与 5 制品三者同构可对照。

### 1.7 执行顺序（worker 单轮 SOP）

1. L1 sanity 探针 `What is 1+1?`（30 s 超时上限）→ 失败即停，报网关问题（不烧 cells 预算）；
2. 30 cells 串行主跑，逐 cell append checkpoint；
3. `status` 判定：COMPLETE（30/30 attempted，超时计错也算 attempted）→ L2；否则触发一次**整轮重跑**（沿仓库先例：worker_a 首轮 minimax run 因 gsm8k_1 60 s 超时被整轮替换而非补跑——minimax runner note 原文 `Replaces the previous worker_a … run`）；
4. L2 制品构建＋自检五项；
5. L3 复算（§1.4）＋ 5 制品 before/after；
6. 对照表三层 JSON＋一页纸汇总；
7. 两次尝试仍 PARTIAL → 如实交 PARTIAL（n/30 逐 cell checkpoint 全量披露）＋升级 Mavis/user 决策（换 backbone 属新 run 声明，不静默改 model ID）。
