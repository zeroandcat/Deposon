## 1. 原创性（Originality）

**评分**：**6 / 10**

**优点：**
- 把"错误路径的可逆复活"识别为 CoT/ToT/SC 的结构性缺口（§1），并以"守恒 + 不可逆淘汰 + 逐路径审计"三要素作为统一判据梳理四条相关脉络（§2 小结），问题定位有独立视角。
- "约束-保真权衡"的双向判读框架（§4.2）与负面结果如实报告（§4.6 G2、§5.2 G3）构成对"物理层增强"类研究的元方法论贡献，这在文献中确实稀缺。
- C3（消融失效模式根因：答案-筛选脱钩、陷阱不可达）虽是调试记录，但作为可复用的消融设计教训有社区价值。

**问题与建议：**
- 🔴 **Major**：**"统一极限命题"的原创性主张过强**。§3.1 自认式 (2) 是构造性定义、归一化是"设计选择而非 S 矩阵推论"（附录 A.3），式 (1) 的 Lorentzian 只是把 Breit-Wigner 线宽取为 1（附录 A.2）。那么"统一"的全部数学内容实为"三参数 softmax 型归一化权重在两个参数边界上的极限行为"——这是一句话的观察，不是一个命题。Feshbach 形式（式 (4)）按作者自己的声明既不导出式 (2) 也不产生任何可检验预测。→ 建议：把"统一极限命题"降级为"参数化设计"，删除或大幅压缩 §3.1 与附录 A 中暗示理论深度的表述；若要保留理论主张，需给出至少一个由 Feshbach 形式导出、且非构造平凡的定量预测并用实验区分。
- 🟡 **Minor**：Related Work 遗漏了与"表面关联陷阱"最直接相关的实验传统：[36] GSM-Symbolic 只在引言被引用一次，但其"无关数字诱饵"设置与本文陷阱分类学（附录 B.2）几乎同构，§2(a) 却未讨论；亦缺 verifier-guided search / 过程奖励模型引导搜索（区别于 [9] 的训练设置）等近期工作。→ 建议在 §2(a) 补一段与 GSM-Symbolic 的设置级对比，并说明自建基准相对它的增量是什么。
- 🟡 **Minor**：贡献 C2 中"<0.2 ms 向量化散射"（§3.2、附录 C.2）作为贡献点过弱（1000 个标量除法的 NumPy 耗时没有信息量）。→ 建议从贡献列表中移除或降级为工程注记。

## 2. 方法论（Methodology）

**评分**：**3.5 / 10**（本维度为论文当前最薄弱环节）

**优点：**
- 消融设计的受控性意识好：五变体共享散射引擎与路径集合、仅改参数（§3.4）；label-shuffle 保持类型数量不变（§4.1）；v1.7.1/v1.8 全部复用同图同种子同负采样协议并有 SPEC 预登记与 prompt_sha256 落盘（附录 D.5/D.6，已对照 SPEC_v1.8.md 核实）。
- 根因分析的机制链完整可复现：93 题失败→final_score 恒 1.0 并列→稳定排序退化为 BFS 顺序→诱饵边权 0.9>0.6（§4.1），这是教科书级的失败归因。
- 统计检验选择恰当：精确 McNemar 双侧、Wilson 区间、配对 bootstrap（B=20000，seed 固定），且明确拒绝用不显著 p 值做正向主张（附录 D.5 末）。

**问题与建议：**

- 🔴 **Major（M1）**：**两个"真实基准"的概念图同样注入了对抗性诱饵边权，且论文未在 §4.2/§4.3 披露**。论文在 §4.1 已承认合成基准的 no_deposon 7% 是"诱饵捕获基线"（诱饵边权 0.9 vs 正确边 0.6，源码注释明示目的是"使贪心游走被陷阱捕获"），并将头条效应量重述为相对 uniform-params 中性对照。但我核对 `deposon_agents_v1_4.py`（第 848–916 行）发现：**GSM8K/StrategyQA 的图构造沿用了完全相同的对抗权重**——正确链 N1→OP1 边权 0.6（第 848 行），而 LLM 自陈 trap 注入边权 0.9（第 890/899 行）、模板注入 Trap_Order 边权 0.85（第 908 行）、且**每题无条件注入 Trap_DeadEnd 死胡同、边权 0.8**（第 914–916 行）。这意味着 Table 10 的 no_deposon 2.0%、Table 12 的 12.1% 与"unified vs no_deposon p=4.4×10⁻²⁴ / 1.8×10⁻¹⁶ 极显著增益"（§4.2/§4.3、摘要）**度量的是同一种人造构造下的增量**，而不是真实分布上的防捕获价值。→ 必须修改：(i) 在 §4.2/§4.3 正文与 Table 10/12 行注中明确披露真实基准图构造含上述注入边权与每题强制死胡同；(ii) 删除或重述摘要与 §4.3 中"相对无场基线保持极显著增益"的表述（该基线在真实基准上同样是退化基线）；(iii) 补一组在**去除对抗边权（等权或语义置信度加权）的 GSM8K 图**上的 no_deposon 对照——若等权贪心在 GSM8K 上远高于 2%，则当前 §4.2 的 Δ(unified−no_deposon)=+0.83 基本不携带真实信息。

- 🔴 **Major（M2）**：**缺少能把"物理层增量"与"标签信息增量"分离的关键平凡基线**。label-shuffle 跌至 17.2%±6.4%（Table 6）已经证明准确率由类型标签承载；labelfree（Table 8）只是把标签换成边权签名，而边权又是 label→weight 转写（作者如实承认）。但全篇缺一个最直接的对照：**"decompose + 按 trap 标签直接规则过滤候选路径 + fold"（不经过任何散射/耗散机制）**。若该基线也达 100%（几乎可以预期，因为 GSM8K 的 trap 节点本就是 LLM 分解器在 decompose prompt 中被要求自陈的"最易诱发的 1~3 个错误做法"，见 `deposon_agents_v1_4.py` 第 533–543 行 DECOMPOSE_PROMPT），则三通道散射对准确率的因果贡献为零，物理层只剩审计表征的价值——这恰恰应是论文的诚实结论，但目前被回避了。→ 必须在合成基准与 GSM8K 上各补一组 rule-based label-filtering 基线；若其与 unified 打平，摘要与 §5.1 的价值命题须重写为"审计表征"而非"路径筛选"。

- 🔴 **Major（M3）**：**合成陷阱基准从未报告"同一 LLM 直接作答"的准确率，基准的难度前提未验证**。§4.1 的全部对照都在"概念图 + 选路"框架内（no_deposon / uniform-params / label-shuffle），但论文从未报告 kimi-for-coding 用 CoT 直接回答这 100 道陷阱题能拿多少分。若直接 CoT 也能 ~95%+（这些陷阱由模板生成、模式有限），则"陷阱集是表面关联误导的受控极限"（§5.1）的前提不成立，+0.90 的防捕获增益是对一个对该模型并不困难的人造分布的增益；若 CoT 确实低，那正是"陷阱真实"的最直接证据。→ 必须补报同一后端在两基准上的 zero-shot CoT 准确率（题目与缓存体系现成，成本约 200 次调用），并将其作为 §4.1 的参照行。

- 🔴 **Major（M4）**：**判定阈值与绑定参数全部在测试分布上手调，无 held-out 验证、无敏感性扫描**。路径命运阈值（max R>0.7 / max A>0.5 / score>0.1，§3.2 第 4 级与附录 C.4）、类型绑定（trap g_couple=5.0 vs 其余 0.05–0.3）、度数修正 0.02、BFS top-8/候选上限 30——全部参数只在 seed=42 的同一 200 题上出现一次，且 100% 饱和意味着参数-阈值余量（trap 节点 R=0.839 vs 阈值 0.7，Table 7）恰好在测试集上"够用"。审稿人无法判断这是泛化能力还是 design-on-test。→ 建议：(i) 划分 dev/test（如 seed=42 调参、seed 43–47 只测）；(ii) 补阈值敏感性表（R 阈值 ∈ {0.5,0.6,0.7,0.8} × score 阈值 × 绑定强度扫描），报告准确率-阈值 plateau 宽度；(iii) 将"η 连续扫描留作未来工作"（§3.1）至少做一个粗网格——这是统一命题最直接的可检验推论，不做难以服众。

- 🔴 **Major（M5）**：**"确定性评测"混淆了"缓存可复现"与"管线稳定"**。§4.5/附录 C.3 的零方差来自 100% 缓存命中（1678 次命中、0 次 API 调用）；概念分解只做过**一次**（n=1 次分解运行、单一模型标识、单一日期 2026-08-22）。LLM 分解的采样/prompt 敏感性被缓存冻结而非被测量。局限 (9)(12) 提到跨模型与一年尺度，但回避了最小可做的稳健性：**同一后端不同采样 seed（或关闭缓存重跑）下，分解图与 100% 准确率是否稳定**。→ 建议至少 3 次独立分解运行（温度>0 或不同日期），报告准确率与图结构（节点/边集合）的变异；若 100% 依赖单次分解的运气，结论强度须相应下调。

- 🟡 **Minor**：§4.2 的"先承诺判读框架"无公开时间戳证据（repo 提交历史或预注册存档）；v1.7.1/v1.8 有 SPEC 文档是好的开始，但 GSM8K 主实验的"实验前承诺"目前只能信作者自述。→ 建议给出可验证的预注册指针（带哈希的提交/tag）。
- 🟡 **Minor**：GSM8K 子集为 seed=42 单次抽样 100 题、无分层；CoT 97% 显著高于文献中同基准典型值，子集偏易的可能性未讨论。→ 建议补报子集难度分布（步数分布已有 Table 11，可与全测试集对比）或换用 GSM-Symbolic 的受控变体集。
- 🟡 **Minor**：§4.7 的 LLM 先验实验全程 n=1 次 API 调用/臂（E1–E4 各 1–2 次 HTTP 尝试，附录 D.6）。E1 的"9/9 边集一致"检验的是确定性模板下的输出稳定性，E4 的单次"弃权"可能是指令遵循（prompt 允许空数组为合法弃权，SPEC A2）而非语义依赖的证据；"最强形式的支持"（§4.7 iv）超出单次观察所能支撑的强度。→ 建议：每个对照至少 3–5 次独立调用报告一致性比例；E4 结论措辞降为"与语义依赖一致的一次观察"。

## 3. 结果（Results）

**评分**：**4 / 10**

**优点：**
- 抽查的数字全部与 `results/` 一致：Table 13 六臂（hybrid 0.367/0.294/0.406、field 0.327、random 0.327/0.412 等，`deposon_v17_fusion_fix.json`）、D.4 配对统计（hybrid@1.0 vs field：2/0，p=0.5；vs random：11/9，p=0.824，`deposon_v16_paired_stats.json`）、D.5 的 p=0.227（8/3 不一致边，精确二项核算吻合）、fixed_sampler 口径（field 0.286 / random 0.388 / hybrid_raw@0.5 0.327，`deposon_v17_fixed_sampler.json`）、GSM8K 主口径（97.0/85.0/2.0、b=0 c=12、p=4.88×10⁻⁴，`deposon_benchmark_v1_4_gsm8k.json`）、StrategyQA（b=4 c=7、p=0.549 核算吻合）、SC@5=96.0%（`deposon_benchmark_v1_4_sc5.json`）、分层 Table 11 与 `deposon_gsm8k_stratified.json` 一致。数字诚信无问题。
- 负面结果的报告密度罕见：预注册预言被证伪（Table 11）、G2 原记录未复现并如实替换（Table 9 表注）、G3 路径长度偏置与势垒-语义错配（§5.2）、tie-artifact 归档（D.5）。

**问题与建议：**

- 🔴 **Major（R1）**：**high_couple 别名 bug 在 v1_4 中并未修复，论文内部自相矛盾且未披露**。§4.1 用整段行注（Table 2/3）、Table 5 整行与附录 C.4 宣布"high_couple 修复（全场 g_couple×3）后耗散 0.263/0.267"；但 `deposon_agents_v1_4.py` 第 1515 行 `'high_couple': {'mode': 'v1_blocking', ...}`——**GSM8K/StrategyQA 的 high_couple 仍是 v1_blocking 的别名**。这解释了两表中 v1_blocking 与 high_couple 逐位相同（Table 10：86.0%/86.0%；Table 12：89.9%/89.9%）且 GSM8K high_couple 平均耗散恰为 0.0（`deposon_benchmark_v1_4_gsm8k.json` variant_results），与 Table 2/3 修复后数值（0.263/0.267）矛盾。附录 C.4 的版本-结果映射明确说 Table 10–12 由 v1_4 产出，即论文知道或应当知道该列在两个真实基准上是无效重复列。→ 必须：修复 v1_4 的 high_couple 定义并重跑，或删除 Table 10/12 的 high_couple 列并加行注说明；同时在 C.4 中修正"修复前误为 v1_blocking 别名"的适用范围声明（该 bug 在 v1_4 仍存续）。

- 🔴 **Major（R2）**：**核心物理卖点"不可逆耗散通道"在全部实验中零可测收益，结论与证据不一致**。汇总论文自己的数据：合成两基准 v1_blocking（零耗散）与 unified 同为 100%（Table 2/3）；GSM8K v1_blocking 86.0% **优于** unified 85.0%（Table 10）；StrategyQA 两者打平 89.9%（Table 12）。即**没有任何一个基准显示耗散通道带来准确率收益**，v1（纯反射）处处 ≥ unified。§4.1 解读 (1) 与 §5.1 已接近承认（"价值在于不可逆性……需要迭代重搜的任务才是预期受益场景（未来工作）"），但摘要、§1 贡献表述与 §6 结论仍以"三通道散射（透射/反射/不可逆耗散）"作为方法卖点呈现，未标注该通道的实证收益为零；§4.2/§4.3 也未讨论"为什么真实基准上 v1 ≥ unified"这一对耗散价值不利的证据。→ 必须：(i) 在摘要与结论中明确"耗散通道的收益主张目前仅有理论动机，全部已测任务上无准确率收益（v1≥unified）"；(ii) §4.2 补一段对 v1>unified 的机制讨论（耗散是否误伤了正确路径？）；(iii) 若要保留不可逆性主张，补一个迭代重搜/多轮搜索场景的最小实验（哪怕玩具规模），否则该主张应移出贡献列表。

- 🔴 **Major（R3）**：**GSM8K 主口径保留了一个已被作者自己定位的 fold_chain bug，并用 post-hoc 敏感性口径对冲——主结果的选择维持了一个可被质疑的叙事**。§4.2 失败归因显示 15 例失败中 10 例是 fold_chain 折叠器缺陷；post-hoc 口径修复后 unified 94.0% vs CoT 97.0%（b=0,c=3,p=0.25，不再显著）。也就是说，"信息损失代价主导"（摘要、§5.1 权衡叙事的核心证据）中约 9 个百分点来自一个**已识别、可修复的工程 bug**，而非约束层本身。保留 bug 版为主口径、修复版标注 post-hoc，技术上透明，但审稿人必然会问：为什么已定位的 bug 不修？若主口径报 94%（p=0.25），"约束-保真权衡"的故事将大幅弱化——当前的选择客观上保留了更有戏剧性的数字。→ 必须：修复 fold_chain 并重跑作为**新主口径**（或至少双口径并列呈现且对新主口径重做分层 Table 11 与 StrategyQA）；若坚持保留现主口径，需在 §4.2 给出不修 bug 的实质性理由（如"fold_chain 是约束层设计的内在部分"——但这与敏感性口径的修复可行性矛盾）。

- 🔴 **Major（R4）**：**§4.7 正文表述超出其附录统计结论所允许的强度，存在正文-附录结论打架**。Table 13 下正文写"判定保持收窄口径：**脑图补全优势成立**……hybrid 在 overall 上为六臂最高（0.367，高于物理/随机的 0.327），named_path 较纯物理臂相对提升 67%"——但 D.4 自己的配对统计显示 overall 差异仅 2 条不一致边（b=2,c=0,p=0.5）、CI [0.000,0.102]，named 差异 2/0（p=0.5）；fixed_sampler 口径下 overall 排序翻转（random 0.388 > hybrid 0.327，D.5(v) 与正文末段均承认）。"六臂最高"在逐位意义上为真、在统计意义上是 2 条边的噪声；"优势成立"与 D.4 的结论"方向性、限定性证据，不是统计显著的一般性结论"直接冲突。→ 必须：将 §4.7 的判定句改为与 D.4/D.5 一致的措辞（如"方向性证据，未达统计显著"），并在 Table 13 中以行注形式标注"overall 排序对负采样口径敏感（fixed_sampler 下 random 反超）"，不要让读者读到正文末段才发现对冲。

## 给作者的整体建议

这篇论文最珍贵的资产是它的**诚实基础设施**：SPEC 预登记、prompt_sha256 落盘、负面结果原样归档、配对统计主动降级——我逐条抽查了约 15 个关键数字，全部与 `results/` 吻合，这在审稿经验中非常少见。问题恰恰在于：这套基础设施目前主要用于**事后对冲**，而论文的头条表述（摘要前段、§4.7 判定句、"极显著增益"措辞）仍然保留了对冲之前的强度。审稿人读完全文再读附录，会产生"正文与附录在打架"的观感（R4 是最典型例子），这比一开始就低调更伤可信度。
