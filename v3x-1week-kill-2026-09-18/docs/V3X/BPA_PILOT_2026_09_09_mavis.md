## 1. 简介

v3 提案 §7 明确: v3 机制对策略性参与者的响应**不激励相容**——`blocked → final_prob × 0.1` 是**外部硬惩罚**,不经过参与者效用函数;被审计方会学习规避"被 block 的特征"而非"变得诚实",直接撞上 Goodhart 定律。v3 提案将**激励相容手术**(外部硬惩罚 → 效用内生罚金,简称 **BPA 协议**)作为一条**附赠臂**:不阻塞 D0–D7 主线、不构成任何核心承诺项、出正/负结果都是有效交付(沿用 §7 "挂不上也是交付"措辞)。

本报告即 BPA 先导数据:在 deposon 散射层 + 22 受控概念图上,以"设计 + 投影数据"形态呈现 2 机制 × 4 任务族的对照骨架,作为 Phase 1 启动前的可行性参考;**不是真实 BPA 实施**。

## 2. BPA 设计(外部硬惩罚 → 效用内生罚金)

| 维度 | 原始 v3(M1) | BPA 协议(M2) |
|---|---|---|
| 惩罚形式 | `blocked → final_prob × 0.1`(乘子) | `payoff − γ·declared_gap + δ·T+R+A_residual`(加项) |
| 路径 | 外在工程乘子,绕过效用函数 | 进入参与者 payoff,可被优化器反向传播 |
| 攻击者响应(理论) | 学习规避 block 特征(Goodhart) | 学习最小化"申报偏差 + 守恒残差"耦合项 |
| 守恒审计 | T+R+A=1 容差 1e-12 不变 | T+R+A=1 容差 1e-12 不变(本约束保留) |
| 失真界 | 失真界未明 | 仍开放(沿用 v3 §6 高压线"守恒 ≠ 真值") |

**设计参数**(默认值,无王老师投入时按此推进): `γ=0.4, δ=0.6`;两者之和 = 1.0,确保从 M1 的"硬乘子"到 M2 的"线性加项"为同量级改写,便于先导对比。

## 4. 探索性结论(不阻塞主线)

1. **设计可行性**: BPA 的"加项改写"在 frozen 守恒残差(2.2e-16)与 BOSS 检出(6/22)两个不变量上保持兼容——可作为 Phase 1 实施的**先验安全性**证据。
2. **真实判死点未到**: 2 机制在先导骨架下不可分;真正判死 M1 vs M2 需要在攻击者效用优化下做"申报偏差 vs block 特征规避"的二选一实验——这是 Phase 1 的工作,不是本 pilot 的承诺。
3. **与 KT-A1 / KT-B1 的关系**: KT-A1 cost multiplier 0.4350(PASS)与 KT-B1 攻击者成功率 0.50%(PASS)的成立**不依赖 M1 还是 M2**——因为两个 KT 都基于 frozen 数据,不触惩罚项;BPA 手术不改变它们的成立。
4. **与 P-B 翼的接口**: BPA 协议是 P-B′(分布报告机制 × 失真界)的**工程前置**——若 BPA 失败, P-B 实验结论无效;若 BPA 通过(攻击者学不会规避), 即可进入 P-B 主线。这也对应 `THINKING_V3_GT_CONTRIB_2026.md` Q5 的高压线。
5. **诚实边界**:
   - 本报告为"设计 + 投影骨架",非真实 BPA 实施;数字全部从 frozen JSON 字段路径引,未手写
   - 2 机制在 22 图上的不可分性**正是先导档的预期结果**,非缺陷
   - 若 Phase 1 启动, M1 vs M2 的真实对比需独立 1-2 天,排在 KT-D0 之后,不在本周 D0–D7 承诺内
