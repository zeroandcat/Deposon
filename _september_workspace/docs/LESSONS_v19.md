# 经验与教训（v1.5–v1.9 全程复盘）

> 2026-08-23 整理。面向后续迭代与同类「AI 自研+自审」工作流的可复用教训。

## 一、科研方法论教训

1. **先证伪采样器，再证伪算法。** v1.7.1「纯物理场 named 输 random」困扰了两个版本，根因不是场无信号，而是反向去噪从 Dirichlet(1) 随机起点出发、50 步收缩后梯度无法重排（信噪比≈0.1）。一行改动（起点换均值）named 0.176→1.000。**教训：负结果先查测量链路的每一环（采样器→协议→统计），最后才查核心假设。**
2. **评估协议本身可以是假象之源。** N_NEG=10 同行负采样既放大场优势（全候选协议下 1.000→0.471），又让随机基线期望随行漂移。凡带采样的评估，必须先做采样器敏感性扫描再谈结论。
3. **对抗性构造会反噬。** v1.4 的诱饵边权设计（0.9 vs 0.6 + 强制 Trap_DeadEnd）本为「压力测试」，但 E9.4 证明即使拉平权重优势仍存——真正的偏置藏在 BFS 短路径优先和免费 `type='trap'` 标签里。**教训：偏置可以藏在你没想过要中性化的维度上；中性对照设计要想「还有哪些免费信息泄漏」。**
4. **平凡基线是诚实底线。** 6 个关键词的规则过滤器追平了整个 LLM+物理管线（0.87≥0.85）。任何「智能」方法的价值主张都必须先过平凡基线这关，且应放在实验设计第一天，而非审稿人指出之后。
5. **n=1 图的一切「显著」都是个案。** 17 条 named 边分布 9 行、共享 48 观测边，有效独立单元=1 张图。图级符号检验 G<6 连显著的可能性都不存在。统计功效分析应前置到实验设计阶段（R3 式 McNemar 枚举 + 模拟），而不是事后补。
6. **λ>1 的「更好结果」是数值 artifact。** hybrid_norm@2 的 0.471 部分来自负场系数把先验空行按场降序排反。超参数网格出了凸组合区间，好事必有妖。

## 二、工程与流程教训

7. **预登记 + 修正案模式有效。** SPEC v1.8→v1.8.1 修正案（设计缺陷如实披露 +  reinterpretation）让 E1 的失败变成了有价值的置换不变性证据。规则：判据先于数据，失败如实归档，事后改判据必须留痕。
8. **缓存优先实验设计 = 零成本迭代。** v1.9 六个实验全部从既有 LLM 缓存离线重放（800 次调用 800 命中），零 API 消耗完成基准整改。前提是缓存带 prompt_sha256 且加载幂等。
9. **并发写共享文件必然丢数据。** SPEC_v1.9.md 被两个 Coder 并发写导致 Part A 整段丢失；论文 md 编辑中被外部恢复两次。教训：①共享文件按 Part 分文件或强制追加-only；②编辑交付必须附 grep 持久性核验（「报告成功但内容缺失」真实发生过）；③主代理对关键文件做完整性 spot-check，不能只看交付报告。
10. **回归测试锁定历史行为。** dirichlet 路径逐位复现 v1.7.1、旧别名仅在显式 legacy 环境变量下复现——修 bug 时把旧行为关进开关，新旧可对照、历史可复现。
11. **verifier 版本化（v1…v10 冻结）+ runs 全记录**是目标模式下的关键资产：每轮迭代可复验，失败运行也留痕，避免了「验收标准随结果漂移」。
12. **「报告中成功」≠「磁盘上成功」。** 修复子代理与复核均发现 edit 未落盘案例。所有自报完成的关键修改，必须由独立方按行号核验。

## 三、写作与评审教训

13. **版本考古文体不属于正文。** 「v1.x 修复了什么」「回应评审质疑」这类元叙事贯穿正文会同时惹恼审稿人（W2 Major）——版本史进附录表，正文只讲科学。
14. **摘要超长在 AI 辅助写作中是系统性偏差**（EN 604 词 vs 250 上限）：生成时总想把所有结果塞进去。约束应写入生成提示词，而非事后压缩。
15. **双评审分工（方法论侧重 + 写作/原创性侧重）检出互补**：A 抓出别名 bug 与对抗构造，B 抓出摘要/编号/耗散零收益，重合仅 2 条。独立复核（第三角色）又抓出编辑过程的回退——「写的人不验，验的人不写」值得坚持。
16. **负面结果写足比藏好。** 本项目信誉几乎全部来自 honesty 段：tie artifact、confshuffle=real、零收益声明、单图个案降级——评审对诚实披露的评价远高于对数字本身的评价。
17. **口语词（「零 API」）进论文会被用户和审稿人双重质疑。** 正式表述一次定义、全文统一（"no LLM API calls issued; inputs read from cache (sha256 on record)"）。

## 四、安全教训

18. **密钥纪律**：临时 API key 全程仅单次命令内联环境变量，verifier 把「密钥前缀扫描」固化为每次验收的必查项——安全约束要变成自动化检查，不靠自觉。

## 五、给下一迭代（v2.0）的置顶提醒

- 多图语料（≥8 张、≥2 来源）是一切统计主张的前提，优先于任何算法新特性。
- 直接 CoT 基线与 §4.2 机制讨论是评审唯一遗留 fail 项，补实验时一并闭合。
- mean-field 效应是否本图特例，只能由多图回答——勿在单图上继续挖掘。
